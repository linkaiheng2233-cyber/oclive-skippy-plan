# 枪娘发行版基础（Distribution Baseline）

**状态**：`CANDIDATE`（2026-11-14，尚无实现）
**目的**：定义"枪娘发行版"是什么、由什么组成、如何版本化与校验、如何安装与回滚，以及它**不许**包含什么。
**上下游**：角色人格与记忆属**兄弟仓 OCLive 角色包 SSOT**（本仓只引用，不复制）；交互与表情映射见 `FRONTEND_DESIGN_BRIEF.md` §9；枪械动作见 `GUN_INTERACTION_MATRIX.md`；红线见 `PROJECT_BOUNDARIES.md`。

---

## 1. 一句话定义

> **一个发行版 = 一次可校验的"内容 + 兼容要求"快照**，把"用哪个角色、怎么互动、要哪版固件"绑定成一个可安装单元；**设备固有状态**（校准值、绑定的模块、Wi-Fi）不属于发行版。

---

## 2. 四层组成与各自的 SSOT

| 层 | 内容 | SSOT 在哪 | 发行版里的形态 |
|---|---|---|---|
| **L1 角色基础** | 人格、记忆模型、基础 Prompt、角色资产 | **兄弟仓 OCLive 角色包** | **只写引用**（`role_ref: {id, version}`），**不复制内容** |
| **L2 枪械交互扩展** | 设备事件 → 角色策略映射（`device_reactions`）、表情词表、预设与阈值 | **本仓定义**（ADR-041/042 的 Gun Interaction Profile） | 实际内容 |
| **L3 固件与资产** | 固件版本要求、资产 blob 版本、表情表 | 本仓 | 兼容要求 + 资产清单 |
| **L4 设备配置** | 模块绑定、IMU 校准、Wi-Fi | 设备 NVS | **不进发行版** |

**为什么 L1 只引用**：复制人格会造成"两个 SSOT"，角色更新后发行版就分叉了（ADR-042 的 fail-open 与"不猜测未知字段"同理）。

---

## 3. 版本与兼容

发行版自身三段版本，**互不替代**：

| 字段 | 含义 | 变更规则 |
|---|---|---|
| `distro_version` | 内容版本（语义化 `MAJOR.MINOR.PATCH`） | 任何内容变化都要改 |
| `requires_firmware` | 需要的固件范围（如 `>=1.3.0 <2.0.0`） | 用到新 ABI 时必须提高 |
| `requires_contract` | 需要的感知契约版本（当前 `0.3`） | 随契约变更 |

**兼容判定（装机前）**：

| 情况 | 行为 |
|---|---|
| 固件版本低于 `requires_firmware` | **拒绝安装**，但设备现有功能不受影响（fail-open） |
| 契约版本不符 | **拒绝安装** |
| `role_ref` 缺失或版本不匹配 | **拒绝安装**（提示"需要先安装该角色"） |
| schema 校验失败 / 摘要不符 / 路径越界 / 体积超限 | **拒绝安装** |

**回滚**：安装采用"临时区 → 校验 → 原子切换 → 保留上一版"，失败自动回滚；**任何失败都不得让设备不可用**。

## 4. 包结构（MVP）

```
distro/
├── manifest.json          # 清单元数据 + 校验和 + 兼容要求
├── expressions.json       # 表情词表（7 个 id → 资源/标签）
├── reactions.json         # 设备事件 → 角色策略（device_reactions）
├── presets.json           # 预设/阈值（如举枪判定阈值、驻留时间）
├── scenarios/             # 可选：场景（.scn.json，见 SCENARIO_FORMAT.md）
├── voice/                 # 可选：离线语音包（PC 播放）
└── assets/                # 可选：额外立绘/字库（与 ffat 资产区同格式）
```

**`manifest.json` 最小字段**：

| 字段 | 说明 |
|---|---|
| `schema_version` | 清单格式版本（独立于内容版本） |
| `id` / `name` / `distro_version` | 身份与版本 |
| `role_ref {id, version}` | 引用的 OCLive 角色包 |
| `requires_firmware` / `requires_contract` | 兼容要求 |
| `files[] {path, sha256, bytes}` | 逐文件校验（**路径不得越界、不得是绝对路径**） |
| `limits {max_total_bytes}` | 体积上限（默认 8 MiB，与 ffat 余量匹配） |

**校验顺序（固定）**：清单 schema → 路径越界 → 逐文件摘要 → 总大小 → 兼容要求 → 内容语义（表情 id 与固件词表是否一致）。

---

## 5. 红线（发行版**不许**包含）

| 禁止 | 原因 |
|---|---|
| 火控、弹道、自动瞄准、辅助瞄准、命中修正 | 产品红线（`PROJECT_BOUNDARIES.md`） |
| 角色人格/记忆的**副本** | 会形成第二 SSOT |
| 任何凭据、内网地址、MAC | 安全 |
| 把"命中/得分"写成感知事实 | 游戏事实必须有独立 provenance，不得注入感知内核 |
| 可执行代码（脚本/插件） | MVP 只允许**数据**；执行能力另立 ADR |

## 6. 与虚拟靶场的关系

| 内容 | 归属 |
|---|---|
| 准星、计分、场景参数 | **靶场（主机侧软件）**，可引用发行版里的预设，但**不得写进感知事实** |
| 表情与反应策略 | 发行版 |
| 感知阈值（举枪判定等） | 发行版（可被设备校准覆盖？待决） |

## 6.5 玩法与内容层：自定义训练场（2026-11-14 所有者方向）

**定位**：借鉴电脑端练枪软件的**玩法结构**（掩体、移动目标、波次、计时），但**产品定位仍是娱乐性打靶**，对外不使用"训练/训练器"作为产品定位；场景内**不实现弹道、初速、下坠、风偏、命中概率、辅助瞄准**。

| 玩法 | 说明 | 场景文件支持 |
|---|---|---|
| 计时挑战 | 固定时长内尽量命中 | `mode.kind = time_attack` |
| 波次生存 | 目标分波出现，漏掉扣分 | `mode.kind = wave` |
| 精度 | 只统计中心区命中 | `mode.kind = precision` |
| 反应 | 目标随机出现，计时反应 | `mode.kind = reaction` |

**地图即数据**：场景用规范 JSON 描述（见 `SCENARIO_FORMAT.md`），**单文件可分享**、可校验、带 `seed` 可复现；建模只用内置图元（`drone`/`dummy`/`plate`/`box`/`wall`），资产可选且缺失时回退内置图元。

**地图的归属**：场景可以作为发行版的一部分（`scenarios/`），也可以**单独分享**（`.scn.json`），两者用同一个校验器。

## 6.6 双屏与屏幕角色

| 屏 | 内容 | 归属 |
|---|---|---|
| **电脑主视口** | 场景渲染、目标运动、命中判定、计分 | 靶场（主机侧） |
| **电脑镜像面板** | **与枪上屏相同的角色画面** | 与设备同一份 ViewModel |
| **枪上屏** | 角色立绘、表情、触摸交互、状态 HUD | `SCREEN_OS.md` |

**双屏互动（NDS 式）MVP 候选**：触摸角色 → 向场景发"干扰/加油"信号；命中/失误 → 角色表情同步；场景提示 → 角色指向。**限制**：下屏输入只能影响表现，**不得影响命中判定**（否则等价于辅助瞄准）。

## 6.7 离线语音包

| 项 | 约定 |
|---|---|
| 播放端 | **PC**（P0 无板载音频；板上 I²S/功放座保留给后续阶段） |
| 内容形式 | 预录音频（优先）或本地 TTS 文本 |
| 触发 | 交互事件（举枪/命中/失误/换弹）或预设短语 |
| 归属 | 发行版 `voice/`，随发行版版本化 |
| 红线 | 不得包含火控/瞄准辅助相关措辞；不得冒充感知事实 |

**板载音频**明确不在 P0（与既有 P0 边界一致），音量设置见 `SCREEN_OS.md` P3。

## 6.8 聊天室（MVP 范围）

| 项 | MVP | 后置 |
|---|---|---|
| 形态 | **电脑侧本地聊天面板**；角色用**本地预设**回应 | 联网多人、云端模型 |
| 板端 | 收到新消息时以气泡/提示呈现（不阻塞角色） | 板端输入法 |
| 数据 | 聊天记录存本地；**不进发行版** | 同步/备份 |
| 红线 | 不把聊天内容写入感知事实；不依赖网络即可运行 | — |
## 7. MVP 落地路径（建议顺序）

| 步 | 产物 | 依赖 |
|---|---|---|
| 1 | `manifest.json` + `expressions.json` + `reactions.json` 三个示例文件 | 无 |
| 2 | **校验脚本**（`scripts/check-distro.ps1`）：schema/路径/摘要/大小 | 1 |
| 3 | 固件侧 `EXPR` 词表与发行版 `expressions.json` 一致性检查 | 现有协议 |
| 4 | 电脑侧台架加载发行版 → 打印解析结果（不做执行） | 1、2 |
| 5 | 安装/回滚流程（临时区 + 原子切换） | 需先定存储位置（设备 or 主机） |

**关键待决**：发行版**装在哪一方**——主机（PC）还是设备（ffat）？这决定第 5 步的形态。

## 8. 待决问题

1. **存放位置**：发行版内容装 PC 侧，还是下载到设备的 ffat？（影响体积上限、离线可用性、更新流程）
2. **校准参数归属**：IMU 零偏这类"设备个体值"放 L4（不进包）是否会让发行版跨设备不通用？
3. **表情词表**：固件内置 7 个词 vs 发行版可扩展词表——后者需要固件动态加载与资源绑定。
4. **执行能力**：将来是否允许 `reactions.json` 之外的小型规则脚本？（现在明确禁止）
5. **多发行版共存**：设备上允许装几个？切换是否需要重启？
