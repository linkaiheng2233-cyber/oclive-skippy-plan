# 四季宝器灵实施路线

本文是本仓路线 SSOT。阶段按验收门推进；后续想法进入 backlog，不直接扩大 v0.1。

## 当前状态

- S0 仓库和基础协议：进行中。
- S1 器灵模拟器：未开始。
- Linux L0 纯 headless 依赖：已完成，默认依赖树不含 Tauri/WebView。
- 原型载体：森柏龙 RADIAN MODEL 1；执行 kit-first，不直接上枪开发。
- 真实硬件：未采购、未开发。

## S0：规格冻结与仓库骨架

目标：用一张事件—输出表描述完整拿起到放回体验。

- [x] 建立独立仓库和 OCLive `robot-soul` 无头骨架。
- [x] 固定仓库边界、非目标和 v0.1 范围。
- [x] 写出 DeviceEvent / Visual OutputCue v0.1 JSON Schema 初稿。
- [x] 记录通用导轨机械接口、无内部走线原则和传感器候选矩阵。
- [x] 写出 SensorObservation v0.1 初稿，并冻结「导轨主机 + 一个 BLE Grip Node」拓扑。
- [x] 冻结相机侧屏大小、屏幕后置主电池和三轴恒扭矩显示机构方向。
- [ ] 为 AN94 固定把玩/射击两种模式的事件—输出映射。
- [ ] 为 schema 增加有效/无效样例与自动校验。

验收门 G0：节点观察、六个语义事件、一个屏幕输出协议和两种模式没有未定义的核心状态。

## S1：器灵模拟器

目标：在 Windows 开发机上不用硬件完成器灵闭环。

- 键盘/测试面板模拟拿起、举起、触发、放回、模式切换和断网。
- 实现 `Sleeping → Held → Ready → Active` 状态机。
- 实现事件去重、乱序、过期、冷却和日志回放。
- 用 AN94 `visual_state_id` 驱动 PNG。
- 用本地模板生成即时屏幕状态，不接语音或触觉输出。
- 连续回放 100 次标准序列。

验收门 G1：无重复回合、无状态卡死；断网时仍能完成拿起—放回反馈。

## S2：OCLive 输入来源契约

目标：传感器回合不会伪装成用户发言或污染角色状态。

- 在 OCLive 主仓设计兼容的 `TurnOrigin`。
- 增加或内部推导回合副作用策略。
- sensor 默认跳过用户情绪、记忆、好感、关系和人格演化。
- 设备审计与聊天存储分离。
- 先写失败测试，再实现契约。

验收门 G2：同一传感器事件重复运行后，聊天、长期记忆、好感和人格无非预期变化；普通用户对话不回归。

## S3：桌面纵向闭环

目标：模拟器通过真实 OCLive Host 调用 AN94。

- 即时反馈先发生，Fast 动态回复后到达。
- `visual_state_id` 与本地 HUD 状态进入统一屏幕仲裁。
- 记录事件进入、即时屏幕反馈、首字和动态画面接管时间。
- 模拟超时、失败、取消和迟到回复。

验收门 G3：连续运行 2 小时；即时反馈规划目标 p95 ≤150ms；模型失败不导致 UI 卡死或设备状态丢失。

## S4：单机硬件原型

目标：先做与载体完全分离的桌面套件；ARM Linux 上无需人工 SSH 即可完成传感器—云端 OCLive—屏幕闭环。

平台 bring-up 与系统服务细节见 `LINUX_ARM64.md`。

套件边界、板端/云端分工与上枪顺序见 `PROTOTYPE_KIT.md`。

最小硬件：具备 BLE Central 能力的小型开发板、约 3.0 英寸级小屏、固定在导轨根部的 IMU、一个物理测试按钮，以及一个薄膜压力 + BLE 的 Grip Node。主机 USB 桌面电源先行，再做屏幕后置 1S 可充电池和三轴屏幕舱；Grip Node 先用桌面电源完成协议和校准，再增加可更换 CR2032。状态判断不依赖磁性底座。

- 启动 OCLive Host 并加载角色包。
- 接屏幕、IMU、按钮、Grip Node 和 watchdog。
- 节点只发送低频 SensorObservation；导轨主机融合握持与运动证据，不上传压力/IMU 原始流。
- 通过 Wi-Fi/手机热点调用云端 LLM；断网时保持本地屏幕状态机。
- 实测 RSS、冷启动、温度、事件延迟和两小时稳定性。
- 实测主机屏灭/屏亮/Wi-Fi/BLE/云端回合功耗，按 4 小时 Alpha 与 8 小时设计目标计算电池。
- 断网重启仍可进入本地模式。
- 用主电池等质量假体验证三轴力矩、导轨固定、收纳泡棉和跨轴线缆后，再冻结电芯、模块布局和 RADIAN 导轨适配。

验收门 G4：自启动可用；连续 2 小时无崩溃、事件风暴和明显过热降频；Grip Node 用 CR2032 完成一次 8 小时功耗回放，低温/低电重连无 brownout；主机电池完成 4 小时完整负载 Alpha，边充边用和低电关机正常。

## S5：实体结构与场地 Alpha

目标：套件闭环通过后，先做 RADIAN MODEL 1 的非功能安装适配，再上枪验证它不只是一次性新奇玩具。

- 实测 RADIAN MODEL 1 导轨槽位、瞄具/操作净空、重心和屏幕视角。
- 以刚性夹具 + 三轴屏幕舱实现多导轨位置展开；任一屏幕转轴调整都不得改变固定 IMU 的载体姿态。
- 采用通用电子核心 + 可更换皮卡汀尼底座；快拆、非承力，首版不接内部火控、扳机或供弹机构。
- 先用断电套件检查装配与操控，再进行通电静态测试，最后进入场地测试。
- 至少三次真实场地测试。
- 记录误触、漏触、重启、断连和主动互动次数。
- 3–5 名非开发者盲测。

建议验收门 G5：

- 核心事件识别成功率 ≥95%。
- 明显误触发 ≤1 次/小时。
- 连续操作时屏幕不冻结、不残留过期状态。
- 不妨碍正常握持、瞄具和安全操作。
- 至少 3 名体验者中有 2 名愿意下次继续使用。

## S6：增强候选

只有 G5 通过后才恢复排期：

1. Shoulder Node 和更多 BLE 低功耗功能节点。
2. 拉栓、上弹、击发等确定性机械事件。
3. 触觉反馈。
4. ASR、TTS 与手机侧车语音能力。
5. 更多角色和器灵场景。

相机、录像、拐角观察、AI 视觉、精确弹药计数和 Live2D 必须独立立项，不进入器灵核心。
