# 板屏与一体式主机舱供电设计

**SSOT 范围**：本文负责 P0-A 晶彩板屏与 P0-B Linux 主机舱的供电拓扑、测量与升级门。连接器与硬件身份由 `HARDWARE_IMPLEMENTATION_PLAN.md` 维护。
**最后更新**：2026-11-13
**状态**：Current

## P0-A：晶彩一体板供电候选

`CANDIDATE`，样机目前只有 USB 供电证据。每个外置传感器从同一套件取电，PC 通过局域网通信。现场附件电源和发射器原供电独立。电池优先放板屏背面的独立托盘，贴近固定底座，避开已确认的天线区和主要热源。屏背空间或射频不足时比较底座固定侧腔。 [候选布局](MECHANICAL_INTERFACE.md#p0-a悍迪-191-原型布置候选)

| 阶段 | 供电链 | 选用条件 |
| --- | --- | --- |
| USB 调试 | `电脑 USB-C → 晶彩板 → 板上 3.3 V → IMU / FSR` | 先复用现有数据线，做固件、触摸与传感器联调。P5 空置。 |
| 无线与测功耗 | `独立稳定 5 V USB 电源 → USB-C → 晶彩板` | 可用有余量的 5 V/2 A 电源作为台架起点，该额定值是电源供给能力。沿用已能上电的线，准备最终供电时单独核对所选 USB-C 电源和线材能否正常上电。PC 连接仅经 Wi-Fi，P5 空置。 |
| 内置电池候选 | `受保护 1S LiPo → P5 → 板载电源管理 → 板屏与传感器` | 先确认电池规格、保护、电池口极性及板载充电规格相容。再用 USB-C 在台架实测充电电流、终止及温升。首件按运行与充电分开设计。边充边用由实际负载分配、插拔切换和充电终止测试裁决。 [接口与极性核对](HARDWARE_IMPLEMENTATION_PLAN.md#011-原厂手册核对2026-11-09) |
| 内置供电回退 | `完整受保护的电源模块 → 稳压 5 V → 晶彩 USB-C` | P5 路线无法确认充电、断电或峰值行为时，先用可持续低负载输出的成品电源延续验证。独立电源使用自身充电入口，晶彩板只接其 5 V 输出，P5 空置。此方案多占稳压/连接空间，实测自动休眠、压降和温升后再评估是否能装入。 |

**上电和充电。** 台架先用 USB。电池路线先在断电状态核对 P5 的真实 GND 针位、同一连接器的方向和插头极性，读取 U2 丝印及厂商确认的单节充电规格。按匹配电芯允许的充电终止电压、电流、温度和保护条件验收；试制优先选有数据手册和保护板的常规 1S 电池。图纸的 SW1 接 U2 的 KEY，关屏、软关机和长期收纳的断电能力分别用实测验证。默认用一个电源输入联调，充电和 USB 数据同时接入的组合单独验证。 [原厂产品资料](https://www.guition.com/esp32-display-module/3-5-inch-esp32s3-display-module) · [原厂接口核对](HARDWARE_IMPLEMENTATION_PLAN.md#011-原厂手册核对2026-11-09)

**低电与显示。** 亮屏、调暗、关闭背光分别测量，单独显示黑图仍可能维持背光功耗。首轮可用 IMU 持续静止和触摸空闲计时试背光调暗，动作或触摸唤醒；它只控制显示电源，正式 `Standby` 仍按感知契约判断。P5 方案通过后，用万用表对照 GPIO5 的电池采样。按 V1.0 图的 33 kΩ / 100 kΩ 分压，若电池为 4.2 V，ADC 输入估算约 3.16 V，高于乐鑫给出的 S3 高衰减有效范围上沿，需实测饱和点。首件只做可验证的低电提示与关机行为，按电芯资料和负载压降设阈值，收纳前确认停机残余电流。 [乐鑫 S3 ADC 范围](https://docs.espressif.com/projects/arduino-esp32/en/latest/api/adc.html#analogsetpinattenuation)

**充电温度（2026-11-13 评审补记）。** V1.0 图纸上 P5 只有电池正负两线，U2 未画出 `TS/NTC`，电芯温度监测在样机上尚无证据。P5 路线须用自带 PCM 的电芯，充电需有人看守，并按电芯规格验证温升。充电终止与电芯温度分别核对。GPIO5 的高电压段可能超量程，首件只验证低电提示。充满状态需要独立证据。 [固件与分区约束](HARDWARE_IMPLEMENTATION_PLAN.md#013-p0-a-固件与分区约束2026-11-13-评审补记)

### 用实测选择容量

用 USB 功率表或记录型电源记录平均 W、峰值 A、板端最低 V、测量时长、环境温度及关键热源温升。功率表刷新慢时，短时压降以示波器或有足够采样率的电源记录为准。至少覆盖冷启动、屏幕常用与最高亮度、背光关、Wi-Fi 入网/重连、连续换图和采样并发，记录无外壳和装壳后的差异。真实使用模式的平均功率用于续航，峰值与最低电压用于查掉电重启。P5 接入后重测电池端电流与消耗，复核充电电流、插拔瞬间、低电关机、静态耗电和温升，核对与电芯规格的一致性。 [项目硬件验证基线](PROJECT_BASELINE.md#43-测量与停止规则)

用 `容量(mAh) = 平均负载(W) × 时长(h) × 1000 ÷ [标称电压(V) × 转换效率 × 可用电量比例]` 做估算。下表以 3.7 V、4 小时、80% 转换效率和 80% 可用电量演示；4 小时是讨论场景，效率和可用比例是估算占位，量产容量与续航目标由后续实测与使用时长确定。

| 平均负载示例 | 4 小时所需标称容量（约） |
| ---: | ---: |
| 0.6 W | 1,010 mAh |
| 0.9 W | 1,520 mAh |
| 1.2 W | 2,030 mAh |

先验证常用亮度和待机策略能否让电池留在薄壳内。临时装配只用等尺寸、等质量假体。首件电池以**达到实际所需时长且装配不过厚**的最小合格规格为准。

以下 §1–§7 为 P0-B 独立 Linux 主机舱。

## 1. 电源域

```text
complete protected 5 V power source
  → protected distribution
      ├── Orange Pi Zero 3W 6GB / A733 + board-mounted cooling
      ├── HDMI screen + USB touch
      └── P1 USB hub/camera (later)
```

主机电源与前/后BLE节点的1S LiPo完全独立。P0不拆成品电源、不改电芯、不用PD诱骗请求9/12V。旧路线的固定5V/3A级只保留为首个台架检查点，不能假定足以同时覆盖A733、板载风扇、主动DP转HDMI、屏幕和本地3B峰值；先使用可限流且有余量的台架电源测出真实最低电压与峰值，再冻结成品电源。屏幕和主板由分配点分别供电，禁止屏幕反向代供主板。

## 2. 为什么 P0 先用完整成品电源

第一轮目标是获得真实平均/峰值功耗、四小时能量、热与三轴手感数据。完整受保护电源能把自制锂电 pack、充电 power-path、NTC 和低压切断风险推迟到有数据之后。代价是低电遥测、自动休眠和边充边用行为可能不可控；不合格时更换整件，不拆壳修改。

P0 充电时正常关闭 Linux 和负载，不承诺 pass-through。V1 是否定制 1S 升压、2S 降压、监督 MCU 或电池匣，只由 P0 数据触发。

## 3. 功耗与续航测量

输入侧至少记录：关机静耗、启动峰值、屏亮四档、背光关、Wi-Fi idle/传输、两个BLE节点、SQLite/OCLive idle、3B模型未加载/常驻空闲/短句生成/连续压力、一次可选网络回合和P1 UVC。每档记录平均W、峰值W、5V最低电压、温度、CPU throttling和持续时间。

估算只使用：

```text
required_Wh = measured_average_W × target_hours / usable_efficiency
```

效率、可用深度和低温余量必须写清。P0 目标是满足四小时的最小/轻量方案，不提前为八小时堆电池。

## 4. 安全关机

P0 人工闭环：

```text
recessed shutdown request
  → Host stops new work
  → OCLive + Host checkpoint
  → Linux shutdown
  → independent safe-to-cut indication
  → user cuts main 5 V
```

普通充电宝不给 Linux 可信电量时，不虚构自动欠压保存。V1 监督电源若加入，仍复用同一 Shutdown Coordinator：Low 卸载可选负载；Critical Reserve 停新写/新角色回合，限时 checkpoint；监督器收到 ACK 或硬超时后切主 rail。

实体键和最低 System UI 不受 renderer/OCLive 故障阻塞。突然断电、日志写满和数据库恢复在副本卡上做 fault injection，不直接拿唯一数据卡试错。

## 5. 移动舱与回退

P0 电源与屏、板一起移动，换取无跨轴供电线和完整外观。移动质量按屏、板、电源、散热、外壳、接头、线缆与关节从动件总和计算，并用硬件 SSOT 的三档假体测试。

若超过质量退出门：先减电源容量、外壳和非必要接口/改紧凑板屏；仍失败才把电池移到固定导轨底座。后者会新增一根跨三轴 5 V 柔性线，必须重新做弯曲、应变释放、限位、压降、噪声和断线降级评审，不能只改 CAD。

## 6. 背光策略

P0 保持 Linux、BLE 和触摸运行，只管理`active → dim → backlight_off`。黑色画面不等于关背光，不用反复切整个 HDMI 板电源省电。时间窗和唤醒延迟是 HostProfile/实测参数；只有背光策略仍无法达成四小时，才评审环境光、CPU governor/外设电源域或更深低功耗，不先使用可能破坏 BLE/HDMI 恢复的 suspend。

## 7. 冻结门

完成`test-worksheets/04-主机电源与关机测试表.md`和`ORANGE_PI_BRINGUP_WORKSHEET.md`后，才冻结电源料号/能量/布局。至少满足：20 次冷启动、峰值不 brownout、四小时完整负载、背光控制、充电关机流程、低电/硬切行为已知、温升可接受、关机恢复与数据库检查通过。
