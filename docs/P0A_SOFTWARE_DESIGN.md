# P0-A 软件实现设计（一体化板 + PC 宿主）

**状态**：`CANDIDATE`（2026-11-13；与 ADR-069 一致，具体接口待 CP1b/CP2 实测后冻结）
**唯一职责**：定义 P0-A 的**软件分层、任务与时钟、消息语义的分阶段落地、降级行为与验收映射**。
**不负责**：交互与界面规范（见 `FRONTEND_DESIGN_BRIEF.md` §9）· 传感器选型（见 `SENSOR_OPTIONS.md` §P0-A）· 供电（见 `MAIN_POWER.md` §P0-A）· 契约字段（以 `crates/ailive-gun-spirit-contracts` 为真源）

---

## 1. 现状与目标

| 项 | 现状 |
|---|---|
| 板上固件 | Arduino-ESP32 3.0.2 + LVGL 8.3.11，ASCII 串口协议；**已实测**点屏、触摸、7 张表情切换、双向联调（`STATE`→换图、触屏→`TOUCH`/`MOOD`） |
| 感知内核 | Rust v0.3，桌面通过 9 帧 golden；**已证可在 `no_std + alloc` 下编译且输出逐字节相同**（CP1） |
| 板上感知 | **尚未运行**。ADR-069 要求内核跑在板上 |
| 联机 | **尚未实现**。目标：USB 先通，再走 Wi-Fi STA |

**目标（P0-A 闭集）**：板端采样→本地内核融合→即时表情反馈；PC 收状态与事件、下发表达；断连时板端继续本地预设。

## 2. 分层

```
┌─ drivers ────────────────────────────────────────────┐
│ IMU(I²C)  FSR(ADC1)  霍尔(GPIO)  显示(QSPI)  触摸(I²C)  │
└──────────────────────┬───────────────────────────────┘
                       │ 节点侧滤波/去抖/去零偏
┌─ perception（Rust，单一实现）────────────────────────┐
│ SensorObservation → PerceptionReducer → PerceptionState │
│                                    └→ DeviceEvent        │
└──────────────────────┬───────────────────────────────┘
                       │ 状态快照(~1 Hz) + 变化事件(边沿)
┌─ expression（板端即时反馈）───┐   ┌─ comms ────────────┐
│ 优先级/驻留/防抖 → 表情 ID     │   │ USB-CDC 与 TCP 同语义│
└──────────────┬───────────────┘   └─────────┬──────────┘
               │ 只改「当前表情 ID」            │
┌──────────────▼─────────────────────────────▼──────────┐
│ ui（LVGL）：RoleStage + StatusBar + SystemOverlay       │
└────────────────────────────────────────────────────────┘
```

**三条纪律**：
1. **内核只有一份实现**——板上与桌面跑同一套 Rust 代码（CP1 已证等价），不得用 C++ 重写一份状态机。
2. **表情只有一个当前值**——三条通路（触屏/PC/感知）都只改它（见交互方案 §9.2）。
3. **即时反馈不等待 PC**——板端自己出图；PC 的角色回合后到可覆盖。

## 3. 任务、时钟与并发

| 任务 | 周期 | 职责 | 约束 |
|---|---|---|---|
| `sensor_task` | IMU 100–200 Hz，FSR/霍尔 20 Hz | 采样、滤波、去抖、去零偏 | 定频发送；用 `esp_timer_get_time()` 打时间戳 |
| `reducer_task` | 由观测驱动 + 1 Hz tick | 持有 `PerceptionReducer`，产出快照与事件 | **单一 `sequence` 账本**（ADR-067 §二.6） |
| `ui_task` | LVGL 30 fps | 渲染；**不直接读传感器** | 只消费有界队列里的表情指令 |
| `comms_task` | 事件驱动 | USB/TCP 收发、帧解析、心跳 | 先按类型分派，再做类型专属校验 |

- **时间**：只用单调时钟，绝不取 RTC 墙钟参与融合；PC 侧另记接收时间。
- **队列**：`sensor → reducer` 与 `reducer → ui` 都用**有界队列**；满则丢最旧并计数（不阻塞采样）。
- **显示锁**：`bsp_display_lock()` 只允许 `ui_task` 获取；感知路径**不得**碰锁（否则 100 Hz 会被渲染阻塞）。
- **`AIM` 流**（将来）：若启用，走独立账本与独立路径，**不得**进入 `PerceptionReducer`。

## 4. 消息语义分阶段

| 阶段 | 形态 | 判据 | 现状 |
|---|---|---|---|
| **S1 台架** | ASCII 行协议：`PING`/`STATE`/`STEP`/`GET STATE`/`TOUCH`/`MOOD` | 双向联调可复现 | **已通过**（2026-11-13） |
| **S2 帧协议 v1** | 二进制帧 `[magic u16][ver u8][type u8][flags u8][len u16][payload][crc16 u16]`；USB 与 TCP **同一套** | 主机可解析；截断/坏 CRC/未知 type 被拒 | 待实现（CP2） |
| **S3 正式协商** | `NodeHello`（版本+能力集）+ `AssetRef` 表达下行 | 节点可自声明能力 | 属 `GS-CONTRACT-004` |

**S2 的硬规则**（来自 ADR-067 的故障域经验）：
- 传输层**先按 `type` 分派**，再做类型专属校验；
- `STATE`/`EVENT`：严格序号（重复丢弃、倒退拒绝）；
- `AIM`：**不做连续性校验**，丢包即丢、不重传；
- 首连/重连：以**当前快照**建基线，只处理恢复后的新事件，**不重放历史**。

## 5. 降级与失败

| 故障 | 板端行为 | PC 行为 |
|---|---|---|
| IMU 失联/超时 | 相关事实转 `unknown`，表达回 `neutral` 或 `confused` | 按 TTL 标过期，不触发角色回合 |
| FSR 未接 | 前后握保持 `unknown`（**不许伪造**） | 同上；`Ready` 永不成立（规则要求握持+姿态） |
| PC 断连（>3–5 s） | 进入**离线预设**：本地表情轮换/静止 | — |
| 链路恢复 | 建新快照基线；稳定 2–3 s 后再切回自由模式 | 只接受恢复后的事件 |
| 帧错误 | 丢弃单帧并计数；连续超限则断开 | 记录协议故障，不注入内核 |

## 6. 验收映射

| 检查点 | 软件侧判据 |
|---|---|
| CP1 | 同一回放输入，`std` 与 `no_std+alloc` 输出逐字节相同（**已通过**） |
| CP1b | 内核编入 ESP32-S3 后可运行；镜像/堆/PSRAM 有记录 |
| CP2 | S2 帧协议的坏帧/截断/重复/过期用例全过 |
| CP3 | 首颗 IMU：ID/轴向/两点校准/失联转 `unknown` |
| CP5 | USB→Wi-Fi 同一语义；断连预设、重连不重放、延迟有记录 |

## 7. 待定与风险

1. **集成方式**：`no_std` 静态库链入 Arduino，还是纯 IDF-Rust 重写——由 CP1b 的体积/链接结果裁决（见 `HARDWARE_IMPLEMENTATION_PLAN.md` §0.1.3 的结构性提醒）。
2. **镜像余量**：当前 1,537,328 B / 2 MiB 槽；立绘占 ≈946 KB。若把立绘移入 `ffat`（11.875 MiB，空）可腾出 ≈1.44 MiB——但**先测加入内核后的实际体积**再决定。
3. **`AngularRateSample` 未验证**（`GS-CONTRACT-005`）：符号/轴向/量程都属设计值，首颗 IMU 后按协议变更抬版本。
4. **正式 OCLive 接入**：仍按所有者安排暂缓；先用 PC 台架测试程序。
