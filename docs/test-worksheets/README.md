# A.I.Live-ai枪娘器灵硬件到货测试包

状态：OPEN / 用户已报告硬件到货，等待逐件身份核验与填写  
用途：硬件到货后按固定顺序采集`MEASURED`证据，并用一张简表向 wargame 爱好者补问几个原型体验问题。仓库文件是SSOT；桌面副本可直接填写，完成后再交回仓库复核。

## 1. 填写规则

- 厂商页面或数据手册写`DATASHEET`，纸面推算写`ESTIMATED`，亲自测得并保留条件/工具/证据的结果才写`MEASURED`。
- 每次测试记录日期、操作者、硬件批次、固件/内核/程序revision、供电方式和环境温度。
- 照片、视频、串口日志和功耗导出放在同名证据目录，表格中只写相对路径或文件名，不把大文件塞进文档。
- 测量与计划冲突时保留旧估算，新增“原假设→实测→影响→建议”，由ADR决定是否覆盖。
- 用户体验可以由参与者口述、项目所有者代填；只记录原话和最需要复现的问题，主观意见不能直接覆盖安全、契约或架构门。
- 不在唯一系统卡上做异常断电；先制作可恢复镜像并使用专用测试卡。
- 电池测试不得拆开成品电芯、旁路保护、短路或在无人看管时充电。第一次接线先限流、测极性和空载电压。
- 上枪前必须先通过桌面闭环和断电机械假体；P0不得接入火控、电机、供弹或其它执行线路。

## 2. 建议工具

- 数显卡尺、0.1 g电子秤。
- 万用表、USB电压/电流/功率表；可调限流电源优先。
- 温度计或热像仪、秒表；需要分析抖动时使用手机高帧率录像。
- USB转串口、备用MicroSD、读卡器和完整系统镜像。
- 可选：逻辑分析仪/示波器，用于ADC噪声、GPIO边沿和电源压降问题。

## 3. 推荐顺序

0. 先读`../PROJECT_BASELINE.md`和`../HARDWARE_ENGINEERING_GUIDE.md`；“已到货”只记为`REPORTED_RECEIVED`，不得直接等同于型号/电气/兼容性通过。
1. 按`采购核对清单.md`逐项对照实物；填`01-硬件到货清单.md`，拍六面照片，核对丝印、批次、接口、电压和包络。身份不明或受损件隔离，不进入首次上电。
2. 按`02-主机与屏幕测试表.md`及仓库`ORANGE_PI_BRINGUP_WORKSHEET.md`完成Orange Pi、HDMI、触摸、Linux和OCLive。
3. 按`03-无线传感节点测试表.md`分别跑前、后节点，再跑双节点并发。
4. 按`04-主机电源与关机测试表.md`先测台架电源，再计算电池；最后才接field电源管理板。
5. 按`05-机械与场地测试表.md`制作质量假体、验证三轴和导轨，最后进入RADIAN静态/场地测试。
6. 从假体/界面阶段即可按`06-爱好者用户体验反馈表.md`复核本次能够展示的既有决定；场地阶段继续使用同一张简表。决策映射见`../UX_RESEARCH.md`。桌面测试包将两者映射为`09-爱好者用户体验反馈表.md`和`10-既有决策体验复核清单-参考.md`。
7. 只有G5通过并明确启动P1+余弹扩展后，才按`07-余弹融合与弹匣结构测试表.md`拆检备用弹匣、审查循环只读信号并验证磁性随动件；详细边界见`../MAGAZINE_AMMO_ESTIMATION.md`。不得用该实验提前扩大P0范围。

## 4. 阶段停止条件

出现以下任一情况立即断电并记录，不继续“多试几次”：

- 极性、额定电压、充电路径或共地关系不明确。
- 电芯鼓胀、破损、异常升温、异味或连接器发热。
- 主板反复brownout、屏幕反供电、USB口异常热或稳压器超过器件规格。
- 传感结构改变扳机行程、握持安全、原电机底板检修或原机构动作。
- 三轴线缆先于机械止挡受力，或电池/LCD/PCB承担碰撞与夹紧力。

## 5. 测试完成后的交付

将已填写文档、体验回答、证据目录和实际采购链接一起交回。AI接手时先区分硬件`MEASURED`与体验者主观回答，再更新功耗、阈值、包络、HostProfile和ADR；不得用一次主观反馈替代尚未填写的实测。
