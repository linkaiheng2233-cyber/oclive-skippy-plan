# 场景文件规范 v1（Scenario / 地图）

**状态**：`CANDIDATE`（2026-11-14，无实现）
**目的**：让"自定义训练场"的地图成为**可分享、可校验、可复现**的数据文件，而不是编辑器私有格式。
**红线**：场景只描述**屏幕平面上的目标与玩法**；**不包含弹道、初速、下坠、风偏、命中概率、辅助瞄准**。命中与否是**游戏事实**（独立 provenance），不得写进感知事实、不得作为 `DeviceEvent`。

---

## 1. 设计目标与取舍

| 目标 | 做法 |
|---|---|
| 人可读、可手改 | JSON（UTF-8，无 BOM） |
| 可分享 | **单文件**即可自包含；资产用引用，不带二进制 |
| 可复现 | 显式 `seed` + 固定 tick（60 Hz）+ 记录 `scenario_version` |
| 可校验 | 固定校验顺序 + 上限（目标数、时长、文件大小） |
| 向前兼容 | `schema_version` 严格匹配；**不猜测未知字段** |
| 建模简单 | 内置图元（box/sphere/capsule/plane），资产可选 |

**明确不做**：脚本、插件、着色器、任意 URL、任意文件路径。

---

## 2. 坐标与单位

| 项 | 约定 |
|---|---|
| 世界 | **2.5D**：`x` 右、`y` 上、`z` 深度（米，浮点） |
| 目标运动 | 限制在 `z` 平面内的 2D 轨迹（可带深度抖动） |
| 时间 | 秒（浮点），逻辑 tick 固定 **60 Hz** |
| 角度 | 度 |

> 采用 2.5D 而不是完整 3D：训练场的玩法不需要真三维弹道——**弹道本来就不做**。

---

## 3. 文件结构

```jsonc
{
  "schema_version": 1,
  "id": "range-basic-01",
  "name": "基础靶场",
  "author": "user",                 // 自由文本，便于分享时署名
  "seed": 12345,                    // 决定随机生成的可复现性
  "arena": { "width": 12.0, "height": 6.0, "background": "grid" },
  "mode": {
    "kind": "wave",                 // time_attack | wave | precision | reaction
    "duration_s": 120,
    "waves": [ { "at_s": 0, "targets": 3 }, { "at_s": 20, "targets": 5 } ]
  },
  "cover": [
    { "shape": "box", "x": 4.0, "y": 0.5, "z": -1.0, "w": 1.2, "h": 1.0 },
    { "shape": "circle", "x": -3.0, "y": 0.8, "r": 0.6 }
  ],
  "targets": [
    {
      "template": "drone",          // 内置图元组合，见 §4
      "count": 3,
      "hp": 2,
      "path": { "kind": "sine", "amplitude": 3.0, "speed": 1.2, "phase_s": 0.0 },
      "spawn": { "x": -5.0, "y": 1.2, "z": 0.0 }
    }
  ],
  "scoring": {
    "hit_points": 10,
    "miss_penalty": -2,
    "precision_bonus_radius_m": 0.15
  },
  "audio": [
    { "id": "hit", "asset": "sfx/hit.wav" },
    { "id": "miss", "asset": "sfx/miss.wav" }
  ],
  "presentation": {
    "character_anchor": "left",     // 角色在屏幕上的位置
    "character_visibility": 0.8,
    "tint": "#1A2233"
  }
}
```

---

## 4. 内置图元（避免依赖外部模型）

| `template` | 组成 | 用途 |
|---|---|---|
| `drone` | 球 + 两片胶囊（旋翼） | 移动人机目标 |
| `dummy` | 胶囊 + 圆盘底座 | 静止靶 |
| `plate` | 薄板 | 钢靶/翻板 |
| `box` | 立方体 | 掩体/障碍 |
| `wall` | 加长立方体 | 场地边界 |

**资产可选**：`assets/` 里可放自定义贴图/模型描述（仍限简单几何），通过 `asset_ref {id, version}` 引用；缺失时**回退到内置图元**（fail-open）。

---

## 5. 玩法类型（`mode.kind`）

| 类型 | 规则 | 判据 |
|---|---|---|
| `time_attack` | 固定时长内尽量命中 | 总分 |
| `wave` | 按波次出现，漏掉扣分 | 存活/分数 |
| `precision` | 只统计中心区命中 | 命中半径分布 |
| `reaction` | 目标随机出现，要求反应时间 | 平均反应时长 |

**通用限制**：目标数 ≤ 64、时长 ≤ 600 s、文件 ≤ 256 KB、资产 ≤ 4 MiB。

---

## 6. 校验顺序（固定）

1. `schema_version` 必须为 1
2. 必要字段存在且类型正确
3. 数值范围（`width/height > 0`、`count ≤ 64`、`duration ≤ 600`）
4. 路径安全：**只允许相对路径、禁止 `..`、禁止绝对路径、禁止 URL**
5. `template`/`path.kind`/`mode.kind` 必须在白名单内
6. 引用完整性：`audio[].asset` 与 `asset_ref` 必须存在
7. 总大小与资产上限

**任何失败 → 拒绝加载，保留上一场景**（fail-open）。

---

## 7. 分享与版本

| 项 | 约定 |
|---|---|
| 文件扩展名 | `.scn.json` |
| 分享单元 | 单个文件；若引用资产则打成一个目录 + `manifest.json` |
| 版本 | 文件内 `schema_version`（格式版本）+ 可选 `content_version` |
| 校验 | 分享时附 `sha256`（在 manifest 或文件名注释中） |
| 向后兼容 | 只接受 `schema_version == 1`；**不猜测未知字段** |

---

## 8. 与双屏玩法的关系

| 屏 | 职责 |
|---|---|
| **电脑屏（"上屏"）** | 场景渲染、目标运动、命中判定、计分 |
| **枪上屏（"下屏"）** | 角色立绘、表情、触摸交互、状态 HUD |
| **互通** | 场景可通过 `presentation.character_anchor` 指定角色位置；触摸事件可作为"干扰/加油"反馈传给场景（NDS 式） |

5. 存档/回放：是否需要记录 `seed + 输入序列` 以复现一局？
