## 1. 当前资源策略

- P0：OCLive Resource Coordinator 只做资源快照与诊断观察，不拒绝、排队或抢占任务。
- 感知融合、BLE、节点健康、实体键、安全关机和最低限度 System UI 永远不进入可拒绝的资源准入。
- Orange Pi HostProfile 先保留字段骨架，数值由本表实测后填写；桌面默认值不得直接复制。
- P1：只有 ASR、TTS、相机分析、复杂 renderer 和后台生成等可选重任务进入协调；轻任务可进程内，原生重任务可拆为独立 systemd 服务，最终按本表数据逐项决定。
- 本项目复用 OCLive 通用 Resource Coordinator，不复制或派生硬件专用协调器；四季宝只拥有 HostProfile、资源适配器、板卡集成与降级策略。
- 诊断采用维护页健康摘要 + 用户显式导出的完整诊断包；development/field使用两套HostProfile，但共享板卡基线、schema与安全边界。
- CPU量化3B是可选角色表达负载。它必须能单独停止/失败并回到网络模型或审核台词池，不得影响感知、System UI、实体键和关机。

## 9. 回填规则

1. 厂商规格标记 `DATASHEET`，纸面预算标记 `ESTIMATED`，仪器或系统实测标记 `MEASURED`。
2. 每个MEASURED结果绑定板卡、OS、提交版本、接线、电源、环境温度和原始证据路径。
3. 数据推翻计划时，不覆盖旧值；追加“原假设 → 实测 → 新裁决 → 影响文档”的ADR。
4. 不在唯一系统卡上做异常断电破坏测试；使用可恢复镜像和专用测试卡。
5. 完成本表不等于自动定板。显示、无线、功耗、温度、重量和交互门必须共同通过。
