# 传感器候选方案与实测路线

## 1. 约束

- 基础套件不拆发射器，不依赖机内空间和内部走线。
- 同一 DeviceEvent 契约覆盖板载、外部有线和 BLE 节点，状态机不感知传感器品牌。
- 先获得稳定的拿起、举起、触发、放回四类事件，再增加握把、后托和命中等推断。
- 云端 LLM 不处理高频传感器流；滤波、阈值、去抖和事件融合都在板端。

## 2. 方案矩阵

| 方案 | 可感知 | 走线 | 优点 | 主要问题 | 阶段 |
|------|--------|------|------|----------|------|
| 主模块内置 6 轴 IMU | 拿起、举起、姿态、晃动、震动估计 | 无 | 最通用、零额外节点 | 无法确认握持/抵肩；震动事件可能误判 | v0.1 必做 |
| 主模块内置霍尔 + 放置点磁体 | 在架/离架、放回 | 无机内线 | 确定性强、便宜、低功耗 | 需要在放置点布置磁体 | v0.1 必做 |
| 主模块物理按钮 | 模式/测试触发 | 无 | 最确定，方便调试 | 不代表真实机械事件 | v0.1 必做 |
| 主模块接触式压电/震动传感器 | 震动/冲击特征 | 无远端线 | 可补充 IMU 高频震动 | 环境震动、不同载体差异大 | v0.2 试验 |
| 外部表面 FSR/电容贴片 | 握持、压力、接触 | 外部短线 | 数据直观、无节点电池 | 理线、耐用性、不同握持习惯 | 候选 |
| BLE 自供电 FSR/霍尔节点 | 握把、后托、弹匣等远端事件 | 无线 | 不占机内空间、换载体方便 | 电池、配对、重连、节点维护 | G4 后候选 |
| 载体内部电子/机械信号 | 确定性拉栓/上弹/击发 | 需要专用接入 | 精度最高 | 不通用、空间小、涉及拆装 | 专用版后置 |

## 3. v0.1 推荐组合

```text
主模块
  ├── 6-axis IMU
  ├── Hall sensor
  └── physical test/mode button

外部
  └── rack/dock magnet（非电子节点）
```

这组组合可以在没有任何机内线或远端传感器电池的情况下完成：

- 磁体状态变化 → `device.picked_up` / `device.put_down`。
- IMU 姿态与运动窗口 → `device.raised`。
- 物理测试键 → `device.triggered`，仅用于打通软件与屏幕路线。

`device.triggered` 在 v0.1 不宣称是真实击发检测。等主模块上 RADIAN 后，先采集 IMU/震动数据，再决定压电、BLE 节点或专用信号是否值得加入。

## 4. 外部传感器路线比较

### 外部有线贴片

适合快速原型和单一载体调参。使用表面理线，不进入机匣；优势是简单、无需节点电池，缺点是外观和换枪便利性。

### BLE 自供电贴片

更符合通用套件：握把、后托各自是可移动节点。代价是每个节点都需要供电、配对、断线重连、低电量提示和固件维护。因此不与 v0.1 主链并行开发。

### 内部专用信号

只适合作为某一载体的增强适配器。它不能成为 DeviceEvent 协议的默认物理来源，也不能让通用套件依赖 RADIAN 的内部结构。

## 5. 实测指标

每种传感器/算法记录：

- 事件识别成功率。
- 每小时误触与漏触次数。
- 原始采样率、事件输出率和 CPU 占用。
- 从物理动作到 DeviceEvent 的 p50/p95 延迟。
- 不同安装位置、不同载体和跑动震动的影响。
- 阈值是否需要逐用户校准。
- 功耗、布线、节点电池和维护成本。

不能复现的场地问题先保存原始窗口和 DeviceEvent 回放，再改阈值。不得只凭一次手感把实验值写成通用常量。

## 6. 决策门

- v0.1：板载 IMU + 霍尔 + 按钮。
- 桌面套件通过后：比较 IMU 单独与 IMU + 压电的触发特征。
- RADIAN 上枪采样后：决定是否需要外部握把/后托节点。
- 只有外部线显著妨碍通用迁移时，才投入 BLE 节点。
- 任何内部走线方案自动归入专用版，不进入基础套件。
