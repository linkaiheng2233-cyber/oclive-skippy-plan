# 从软件开发者到四季宝硬件工程师

**状态**：CURRENT LEARNING GUIDE  
**最后核对**：2026-09-04  
**用途**：用已有的软件工程认知建立硬件开发习惯；不替代器件datasheet、电池安全要求或具体接线图。

## 1. 好硬件工程师的核心不是“会焊”

对这个项目，最重要的能力依次是：

1. **先定义接口**：知道每条线是谁驱动、谁接收、电压多少、空闲状态怎样、断线怎样失败。
2. **让未知保持未知**：没测过就写`UNKNOWN`，不凭商家图、线色或“通常如此”上电。
3. **一次只增加一个变量**：主板、屏幕、触摸、BLE、电池分阶段接入。
4. **测量而不是猜测**：电压用万用表，电流用功耗仪，数字波形用逻辑分析仪，模拟噪声/瞬态再用示波器。
5. **同时看能量、信息和力**：电流会发热和压降，信号会受干扰，外壳和线缆会传递机械应力。
6. **设计失败方式**：传感器断线应变Unknown，模型崩溃应回退，风扇停转应降载，不能把局部故障变成整机失控。
7. **保留可复现证据**：照片、丝印、批次、接线图、仪器、命令、日志、环境和结论必须能被下一个人复做。

## 2. 软件概念的更准确映射

| 软件 | 硬件 | 要注意的差别 |
|---|---|---|
| 类型系统 | 电压域、方向、额定值、连接器防呆 | 接错不只是编译失败，可能永久损坏 |
| API契约 | 引脚表、时序、I2C/SPI/UART/BLE协议 | 接口同时包含电气和语义两层 |
| 编译器 | ERC/DRC、原理图审查、BOM校验 | 只能发现一部分错误，不能证明实物可用 |
| 单元测试 | 单模块限流上电和功能测试 | 必须包含真实仪器、温度和时间 |
| 集成测试 | 板屏、双BLE、电源、外壳共同运行 | 电源压降、EMI和热耦合只在组合后出现 |
| 日志 | 串口、万用表、逻辑分析仪、示波器 | 软件日志可能在掉电瞬间来不及写出 |
| Mock | 信号发生器、假负载、质量假体、桌面节点 | 用于隔离变量，不能代替最终实物 |
| CI | 自动构建+硬件测试治具+固定工作表 | 硬件CI还必须控制批次、接线和环境 |
| 回滚 | 换回旧板/固件/线束/外壳版本 | 物理返工有成本，因此要保留样件标签 |

硬件不是“没有编译器”，而是编译器只能覆盖原理图和布局中的一部分规则。真正的运行时是现实世界；电压、温度、接触、震动、装配公差和时间都会参与执行。

## 3. 先学会看三条流

### 能源流

```text
电源/电池 → 保护 → 转换 → 分配 → 负载 → 地/回流路径
```

每一级问：额定电压、电流峰值、效率、压降、发热、短路保护和断电后能量去哪。

### 信息流

```text
物理量 → 传感器 → 电压/数字量 → MCU滤波 → BLE → Host事实 → 角色/屏幕
```

每一级问：单位、采样率、精度、时效、校准、Unknown和错误是否会被误解释。

### 力与热流

```text
手/碰撞/夹具 → 外壳/螺柱/止挡 → 导轨
芯片热 → 散热器 → 空气 → 风道/外壳
```

PCB、LCD、电池、焊点和线缆不应成为结构受力件；风扇存在不等于有有效风道。

## 4. 第一次硬件调试的思考模板

以“Orange Pi接屏”为例：

1. **目标**：先证明主板单独稳定启动，再证明显示链，不同时验证触摸和OCLive。
2. **已知**：板卡输入额定值、接口类型、屏幕供电、主动转接器方向。
3. **未知**：实际启动峰值、EDID、800×480时序、USB反供电、散热需求。
4. **最小实验**：主板+系统卡+串口/网络，受控电源单独启动20次中的第一次。
5. **预期观察**：输入电压/峰值电流、指示灯、串口、系统版本、温度。
6. **停止条件**：限流、异常热/味、反复重启、输入电压下跌或接口方向不明。
7. **通过后下一变量**：仅增加主动视频转接与屏幕视频；触摸USB最后加入。

这和软件里先写最小复现相同，只是“变量”还包括电源、线材、接头方向、环境和机械状态。

## 5. 四季宝学习顺序

### 第一阶段：安全与基础测量

- 电压、电流、电阻、功率、能量和欧姆定律。
- 万用表的电压/电阻/通断档；理解为什么电流档误并联会短路。
- 极性、共地、3.3V/5V逻辑、电源额定与限流。
- 输出：能在不上电前画出一条完整能源链并检查连接。

### 第二阶段：FSR与ADC

- 分压器为什么把电阻变化变成电压。
- ADC参考电压、分辨率、采样噪声、滤波、迟滞和断线诊断电阻。
- 输出：用USB供电的单个XIAO读取FSR，保存原始曲线，再定义握持阈值。

### 第三阶段：数字接口与BLE

- GPIO、I2C、SPI、UART各自的方向、线数、距离和故障方式。
- BLE广播、连接、GATT、MTU、sequence、boot id、丢包与重连。
- 输出：单节点发送低频SensorObservation，断线后Host变Unknown而不是猜释放。

### 第四阶段：供电、热与组合

- 稳压、峰值电流、压降、线阻、退耦、USB供电与反供电。
- 电池保护、充电、低电关机；不自行拼装或旁路保护电芯。
- 散热器、风扇、进出风、贴枪遮挡和降频。
- 输出：板屏双节点两小时组合测试和功耗/温度曲线。

### 第五阶段：机械与可制造性

- 尺寸链、公差、螺柱、应力释放、连接器维护空间、材料和重量重心。
- 先质量假体，再断电结构，再通电静态，最后场地。
- 输出：装拆可重复、线缆不受拉、LCD/PCB/电池不受结构载荷。

## 6. 每天结束前的六个问题

1. 今天验证了什么，证据在哪里？
2. 哪些仍是UNKNOWN，而不是“应该没问题”？
3. 这次只改变了哪个变量？
4. 最坏故障会不会损坏其它模块或影响原载体？
5. 下个人能否按记录复现接线、软件和测量？
6. 结论需要更新工作表、领域SSOT、技术债还是ADR？

能稳定回答这六个问题，比一次把所有线接上并碰巧点亮更接近一个好的硬件工程师。
