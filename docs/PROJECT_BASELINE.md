## 1. 一句话目标

制作一个独立于发射器内部机构、安装在标准导轨上的本地实体角色宿主：**枪侧一块 ESP32-S3（含 IMU、FSR 与外部只读扳机霍尔）**观察握持、运动、姿态与只读辅助触点，**PC 作为唯一 Host** 融合为中性设备事件，OCLive 负责角色理解，枪侧小屏与主机显示由 Host 统一表现；接上电脑即可玩屏幕打靶，拔掉电脑仍能靠预设模式陪伴。

## 3. P0交付闭集

**P0-A（当前主线，PC 宿主 + 枪侧瘦客户端）**只承诺以下能力：

1. **枪侧单节点**采集并发送低频、去抖、节点侧滤波后的物理观察（握持接触、运动、重力姿态、只读辅助触点）。
2. Host（PC）在本地融合 Standby、Held、Ready、前/后握、运动、姿态和只读辅助触点；节点按**能力集**绑定，不按写死的两个角色（ADR-065）。
3. 事件先触发确定性屏幕反馈（**枪侧小屏 + 主机侧显示**）；可选 OCLive 角色回合后到并服从 Output Arbiter。
4. 模型失败、链路断连或 renderer 失败时，最低状态界面仍工作；枪侧在断连 3–5 s 内降级到**预设模式**，恢复并稳定 2–3 s 后切回自由模式。
5. 枪侧固件与宿主能自启动；**枪侧能源链可测、可充、可安全降级**。
6. **娱乐后端 G0**（扣扳机 → 主机画面反馈）可玩，且不阻塞以上闭环。
7. 桌面套件通过后才制作导轨支架与整枪安装，再进行 RADIAN 静态与场地验证。

**P0-B（独立主机舱，保留后置）**保留原有 6 条闭集与 G4 门，**不因 P0-A 取消**，只是不阻塞近期进度。

PNG/HUD 属于 P0。语音、相机、Live2D、余弹和更多节点不是 P0 完成条件。

## 4. 硬件开发共同基线

### 4.1 首次接线前

- 为每件器件记录实物照片、丝印、卖家链接、批次、接口、标称电压和连接器方向。
- 断电状态检查短路、异物、焊桥、破损、松动和极性；未知针脚不接。
- 先画能源链和信号链，再接线；每条线同时写明起点、终点、电压域、方向和最大预期电流。
- 第一轮主机/屏幕使用可限流台架电源或已知合规成品电源，不直接设计最终电池包。

### 4.2 Bring-up固定顺序

```text
到货身份与外观
→ 断电电阻/连续性/极性
→ 主板单独上电与串口/系统
→ 屏幕单独供电
→ 视频链
→ USB触摸
→ Host与最低UI
→ 单个BLE节点USB供电
→ 第二节点
→ 双节点共存
→ 节点受保护电池
→ 主机移动电源
→ 外壳与机械假体
→ 上枪静态
→ 场地
```

每一步只增加一个新变量；失败时回到最近一次已通过状态。不得在同一次首次上电同时接主板、屏幕、电池、传感器和未知转接件。

### 4.3 测量与停止规则

- 通电前测极性和断电电阻；通电时先看限流、电压跌落、异常热和气味，再看软件日志。
- 不带条件、仪器、测点、批次和revision的数字不能标记为`MEASURED`。
- 电芯鼓胀/破损、异常升温、极性不明、连接器发热、重复brownout、屏幕反供电或机械件改变原机构动作时立即断电并隔离。
- P0不连接RADIAN火控、电机、供弹或任何执行线路。

## 5. 软件与接口基线

- Rust类型是v0.2感知契约真源，Schema由代码生成；不得直接编辑生成Schema。
- 感知内核不依赖OCLive、BlueZ、GPIO、SQLite或屏幕；Host是唯一组合根。
- 原始ADC/IMU不进入OCLive；节点/驱动先滤波，Host只向OCLive提供有界中性事实。
- 系统提示高于角色提示；迟到RoleCue不得覆盖更新的物理revision。
- 本地3B及以下模型只是可失败表达provider，不阻塞感知、UI、持久化或关机。

## 6. G4完成定义

满足以下条件才称“实体硬件闭环完成”，不能只以“屏幕亮了”或“BLE连上了”代替：

### 6.1 P0-A（当前主线）

- 枪侧固件冷启动 20 次，屏幕出图、感知事件可用，**不需要 SSH 或人工救场**。
- 单节点连续两小时稳定；1,000 条事件无状态卡死或事件风暴。
- 事件到枪侧确定性画面 p95 满足路线门；模型失败不影响该链。
- **断连 3–5 s 内降级到预设模式，链路恢复并稳定 2–3 s 后切回**，且模式切换只改变表达能力、不改变感知与安全语义。
- **陀螺瞄准流（约 100 Hz）的链路抖动与手感有实测记录**：有线与 Wi-Fi 各一轮（Wi-Fi 的 p95 与抖动目前为 `UNKNOWN`）。
- 枪侧 1S LiPo 完成续航、充电温升、低电与恢复测试（开发期 USB 供电的数据不能替代）。
- 娱乐后端 G0 可玩：扣扳机 → 主机画面反馈，时延有记录。
- 所有结果有工作表、日志/照片和对应硬件/软件身份；未通过项进入技术债而不是口头忽略。

### 6.2 P0-B（独立主机舱，保留后置）

- 目标镜像冷启动20次，Host和最低UI可用，无需SSH救场。
- 双节点连续两小时稳定；1,000条事件无状态卡死或事件风暴。
- 事件到本地确定性画面p95满足路线门，模型失败不影响该链。
- Wi-Fi、BLE、屏幕、风扇和候选模型组合下无不可接受降频、brownout或失控重启。
- 主机和节点电源完成续航、充电温升、低电、关机和恢复测试。
- 所有结果有工作表、日志/照片和对应硬件/软件身份；未通过项进入技术债而不是口头忽略。

## 7. 当前第一步

**P0-A 主线（不需要等 P0-B 的显示问题）**：

1. **采购最小集（约 55–130 元）**：ESP32-S3 **N16R8**、**ICM-42688-P（SPI）**（QMI8658 作回退）、数字霍尔（A3144 类）、3×2 mm 钕磁铁、杜邦线/电阻。**屏单独按导轨支架的实际尺寸下单**（ST7789 类 SPI，240×320 级）。**不买**：主机电池、喇叭、相机、投影。
2. **桌面 USB 阶段（阶段 A）**：电脑 USB 供电 + USB-CDC，把「ESP32 → SPI 屏出图」→「IMU 举枪/放下」→「霍尔扳机触点」逐项跑通，每步只加一个变量。
3. **台架实验**（并入 ADR-063 待办 1）：IMU 静止噪声、零偏重复性、温漂、预热时间、100 Hz 节拍抖动；FSR ADC 线性与噪声；Wi-Fi 丢包与 p95。
4. **契约 v0.3**：实现既有 `NodeHello` 协商 + 角速率观测 + `AssetRef` ID 空间 + 只读换弹（`GS-CONTRACT-004`）。
5. **感知内核节点模型泛化**（`GS-ARCH-001`，ADR-065）：**不需要硬件**，可在模拟器上完成，是单节点形态的开工前置。
6. **娱乐后端 G0**：扣扳机 → 主机画面反馈（ADR-066 §8）。

**P0-B 并行项（不阻塞主线）**：
