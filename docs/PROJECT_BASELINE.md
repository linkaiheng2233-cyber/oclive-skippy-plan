## 1. 一句话目标

制作一个独立于发射器内部机构、安装在标准导轨上的本地实体角色宿主：前后无线节点观察握持、运动、姿态和只读辅助触点，Linux主机将其融合为中性设备事件，OCLive负责角色理解，屏幕由Host统一表现。

## 3. P0交付闭集

P0只承诺以下能力：

1. 前、后两个独立BLE节点分别采集并发送低频、去抖后的物理观察。
2. Host在本地融合Standby、Held、Ready、前/后握、运动、姿态和只读辅助触点。
3. 事件先触发确定性屏幕反馈；可选OCLive角色回合后到并服从Output Arbiter。
4. 断网、模型失败、节点掉线和renderer失败时，最低状态界面及安全关机仍工作。
5. Zero 3W、屏幕和触摸能自启动；主机与两个节点的能源链可测、可充、可安全降级。
6. 桌面套件通过后才制作三轴主机舱和可更换导轨底座，再进行RADIAN静态/场地验证。

PNG/HUD属于P0。语音、相机、Live2D、余弹和更多节点不是P0完成条件。

## 4. 硬件开发共同基线

### 4.1 首次接线前

- 为每件器件记录实物照片、丝印、卖家链接、批次、接口、标称电压和连接器方向。
- 断电状态检查短路、异物、焊桥、破损、松动和极性；未知针脚不接。
- 先画能源链和信号链，再接线；每条线同时写明起点、终点、电压域、方向和最大预期电流。
- 第一轮主机/屏幕使用可限流台架电源或已知合规成品电源，不直接设计最终电池包。

### 4.2 Bring-up固定顺序

```text
到货身份与外观
→ 断电电阻/连续性/极性
→ 主板单独上电与串口/系统
→ 屏幕单独供电
→ 视频链
→ USB触摸
→ Host与最低UI
→ 单个BLE节点USB供电
→ 第二节点
→ 双节点共存
→ 节点受保护电池
→ 主机移动电源
→ 外壳与机械假体
→ 上枪静态
→ 场地
```

每一步只增加一个新变量；失败时回到最近一次已通过状态。不得在同一次首次上电同时接主板、屏幕、电池、传感器和未知转接件。

### 4.3 测量与停止规则

- 通电前测极性和断电电阻；通电时先看限流、电压跌落、异常热和气味，再看软件日志。
- 不带条件、仪器、测点、批次和revision的数字不能标记为`MEASURED`。
- 电芯鼓胀/破损、异常升温、极性不明、连接器发热、重复brownout、屏幕反供电或机械件改变原机构动作时立即断电并隔离。
- P0不连接RADIAN火控、电机、供弹或任何执行线路。

## 5. 软件与接口基线

- Rust类型是v0.2感知契约真源，Schema由代码生成；不得直接编辑生成Schema。
- 感知内核不依赖OCLive、BlueZ、GPIO、SQLite或屏幕；Host是唯一组合根。
- 原始ADC/IMU不进入OCLive；节点/驱动先滤波，Host只向OCLive提供有界中性事实。
- 系统提示高于角色提示；迟到RoleCue不得覆盖更新的物理revision。
- 本地3B及以下模型只是可失败表达provider，不阻塞感知、UI、持久化或关机。

## 6. G4完成定义

满足以下条件才称“实体硬件闭环完成”，不能只以“屏幕亮了”或“BLE连上了”代替：

- 目标镜像冷启动20次，Host和最低UI可用，无需SSH救场。
- 双节点连续两小时稳定；1,000条事件无状态卡死或事件风暴。
- 事件到本地确定性画面p95满足路线门，模型失败不影响该链。
- Wi-Fi、BLE、屏幕、风扇和候选模型组合下无不可接受降频、brownout或失控重启。
- 主机和节点电源完成续航、充电温升、低电、关机和恢复测试。
- 所有结果有工作表、日志/照片和对应硬件/软件身份；未通过项进入技术债而不是口头忽略。
