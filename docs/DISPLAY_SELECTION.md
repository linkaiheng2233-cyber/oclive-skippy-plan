# 屏幕、主板与视频接口冻结门

**SSOT 范围**：本文负责显示方案比较与冻结方法；当前型号、功耗/尺寸占位和整机拓扑以`HARDWARE_IMPLEMENTATION_PLAN.md`为准。
**最后更新**：2026-09-23
**状态**：Current  
**相关决定**：`DECISIONS.md` ADR-064（小屏 HDMI 兼容性判定与换屏）、ADR-063（PC 前置形态）

## 1. 当前执行路线

P0 首轮模块化 bring-up 使用：

```text
Orange Pi Zero 3W 6GB / A733
  → 壳内短 USB-C DP Alt Mode 主动转 HDMI
  → 3.5inch 480×800 HDMI IPS touch 候选屏
  → 横向 UI 800×480
```

这里冻结的是接口和验证顺序，不是尚未到货的具体店铺料号。屏幕、主板、触摸、主动视频转接、短视频线与P0完整5V电源位于同一三轴移动主机舱，视频线不跨yaw/pitch/roll。Zero 3W**同时具备 Mini HDMI 与 USB-C DP Alt Mode 两路视频输出**；本基线冻结的路线是 **DP Alt Mode → 主动式 DP→HDMI**，Mini HDMI 直连不是当前路线。Luckfox Lyra Zero W + Waveshare 2.8inch DSI LCD只在移动质量、厚度、功耗或接头包络不通过时作为紧凑回退，不并行开发。

### 1.1 2026-09-23 实测修正：屏侧 HDMI 兼容性成为独立门

首轮板屏联调走的是 **Mini HDMI 直连**（偏离上述冻结路线），结果是：

| 观测 | 结论 |
|---|---|
| 板端 HPD 稳定、驱动成功解析 EDID、设 `480*800`、`hdmi drv has been enable!`、CRTC/平面扫描输出、`/dev/fb0` + fbcon 就绪 | 板卡 HDMI 驱动与链路参数**正常** |
| 同一块屏在 **PC** 上正常显示桌面 | 屏本体与面板时序**可用** |
| 驱动日志 `sunxi hdmi select vic 0 use hdmi14 vsif` | 480×800 是**非 CEA 模式**，走 HDMI 1.4 厂商专用信息帧 |
| 板端只出现一条竖线 | 屏的 HDMI 接收端对该信号组合**不兼容** |

因此 **"屏能作为通用 HDMI 接收端工作"升级为独立的选型硬门**（见 §3），并新增两条不依赖 HDMI 兼容协商的显示路径备选：**DP Alt → 主动转接**（见 ADR-064 决定 2）与 **SPI 小屏由 MCU 直驱**（见 ADR-063 的桌面形态）。更换屏幕之前，先验证 DP 路线（30–80 元）。

## 2. 为什么当前先用 HDMI

| 维度 | Orange Pi + HDMI | Lyra + DSI 回退 |
|------|------------------|-----------------|
| 内存余量 | 6 GB，允许本地OCLive、Web/2D与CPU量化3B候选并行实测 | 512 MB，必须严格裁剪并实机证明 |
| 接口通用性 | 标准 Linux 显示链，替换屏/板更容易 | 板屏匹配更紧，排线更薄 |
| 首轮调试 | 可先在 Windows/普通 HDMI 上验证 800×480 UI | 更依赖厂商镜像、设备树与特定屏适配 |
| 机械代价 | USB-C DP主动转HDMI、HDMI接头/驱动板较厚，必须用壳内短线与包络门约束 | FPC 存在感低，整体可能更薄 |
| 当前角色 | P0 数据获取与闭环 | 重量/厚度失败时的有界回退 |

HDMI 的收益不是“画质一定更高”，而是第一轮更容易获得可替换、可诊断的显示链。若实测证明 HDMI 板、接头与 Orange Pi 让移动舱不可接受，再用数据触发 DSI 回退。

## 3. 屏幕质量要求

采购页面不能只看尺寸和分辨率。候选必须记录：

- **通用接收端门（2026-09-23 新增，硬门）**：必须能在**普通 PC/显卡**上作为显示器正常工作，且 EDID 能被通用 HDMI 源解析出**标准模式**（含标准 CEA 模式，而不是只有厂商自定义时序）。只有"能当普通显示器用"的屏才进入板端联调，避免把屏侧兼容问题误判成主板问题。
- **分辨率与方向**：目标 800×480 横向使用；若面板原生为竖屏（如 480×800），必须同时说明旋转由谁负责（控制台 `fbcon=rotate` / renderer 旋转），不得指望改 mode 解决。
- LCD/显示板完整外廓、厚度、安装孔、接口朝向和线缆弯曲空间。
- IPS 视角、实际亮度、背光档位与软件控制方式。
- 电容/电阻触摸类型、USB HID 兼容和手套/保护片表现。
- 户外可读性、偏振护目镜方向、玻璃反光与最低可用亮度。
- 20 次冷启动点亮率、旋转、花屏/闪屏、睡眠/唤醒和两小时稳定性。
- 25/50/75/100% 背光下整屏输入功耗与温升。

商品图中的“IPS”“高清”“树莓派兼容”不算本项目实测。若卖家无法提供机械图、背光控制说明和触摸接口，仍可做样品，但不能直接锁为产品屏。

**2026-09-23 追加的采购前必问**：① 该屏在普通电脑上能否直接当显示器用（让卖家确认或看买家评价）；② EDID 是否为完整标准 EDID（非克隆/占位）；③ 若走 DSI/SPI，板端需要哪套设备树与驱动支持。

## 4. P0 验证顺序

### D0：桌面 UI

在 Windows/普通 HDMI 输出上用 800×480 构建角色页、状态条与系统 Overlay，确认文字大小、触摸目标、横竖策略和 PNG fallback。不等待 Linux 板卡。

### D1：板屏点亮

Orange Pi使用稳定桌面5V电源，记录镜像/内核/设备树/主动DP转HDMI芯片与屏幕板revision；先显示固定测试图，再运行mock ViewModel。验证EDID、800×480时序、USB touch、旋转、背光、转接温升和20次冷启动。

### D2：资源与共存

在屏亮、Wi-Fi、两个 BLE 模拟连接、本地 OCLive 和日志运行时记录 RSS、`MemAvailable`、CPU/温度、首像素、事件到画面延迟与两小时稳定性。

### D3：机械与户外

把屏、板、接头、散热、电源和外壳放入完整质量/厚度假体，检查天线、热、保护片、泡棉、触摸、偏振和三轴手感。只有 D1–D3 通过才冻结屏幕料号和前脸 CAD。

## 5. 回退触发

满足任一项才重开 Lyra + DSI，而不是凭偏好同时维护两套：

- 完整移动舱超过`HARDWARE_IMPLEMENTATION_PLAN.md`的质量退出门，且减电池/壳体/非必要接口后仍失败。
- HDMI 接头、驱动板和线缆无法在目标厚度内安全隐藏。
- 背光功耗或热导致 P0 续航/温升门无法满足。
- Orange Pi 显示/触摸链出现无法通过更换样屏或镜像解决的稳定性问题。
- **（新增）屏侧 HDMI 兼容性无法通过 DP→HDMI 主动转接或换屏解决**：此时按 ADR-064 依次尝试 ⓪ 免费试 DVI 信令（命令行 `video=<conn>:480x800@60D`，跳过 HDMI 信息帧；**提案·未实测**，见 `test-worksheets/runs/2026-09-23-zero3w-panel-no-image.md` §6）、① DP Alt → 主动转接、② 换"能当普通显示器用"的屏、③ 改用 SPI 小屏（由枪侧 MCU 直驱，不做 HDMI 兼容协商）、④ 退回 DSI 路线。

回退后仍必须保留本地 OCLive、SQLite、安全生命周期、双 BLE 节点和屏幕仲裁；不能用删核心能力来迁就 512 MB。
