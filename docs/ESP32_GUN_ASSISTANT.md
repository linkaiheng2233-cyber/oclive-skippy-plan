## 1. 一句话目标

**枪上不再有主机**：整枪只挂一块 **ESP32-S3 + 小屏**（约 60–70 g，可电池或 USB 供电）。它自己能演「预设模式」；接上电脑主机后升级为「自由模式」，由主机侧 OCLive 提供实时 AI 表达。**体验上限完全由主机性能决定，枪侧硬件不随主机升级而更换。**

## 2. 架构与数据流

```
枪上（轻量助手）                                  主机（电脑，唯一 OCLive 宿主）
┌──────────────────────────────┐                  ┌────────────────────────────┐
│ ESP32-S3 N16R8               │  ── 语义上行 ──→  │ 感知内核：融合/状态机/TTL    │
│  ├ FSR ×1–2（前握/后握）      │   观察 + 边沿      │ OCLive：角色/记忆/SQLite     │
│  ├ IMU（外挂 MPU6050/QMI8658）│  ←─ 语义下行 ──  │ 表达后端：本地模型 / TTS/ASR │
│  ├ 只读辅助触点（扳机）        │  资产引用+文本     │ Output Arbiter              │
│  ├ SPI 小屏（240×320 级）     │   + 状态位 + 模式  └────────────────────────────┘
│  ├ [可选] I2S 麦克风/功放      │
│  └ 1S 电池 + 充电模块          │
│                              │
│  自由模式：表达外包给主机        │
│  预设模式：本地规则表自己播放     │
└──────────────────────────────┘
```

**关键纪律：下行只传语义，不传像素。** 主机只下发「用哪张表情 + 哪句话 + 状态位 + 模式」，素材（表情位图、字库、音效）**预置在 ESP32 的 16 MB Flash**。

理由（带宽账）：240×320 RGB565 单帧 = 150 KB；30 fps ≈ **4.6 MB/s**，Wi-Fi 与 SPI 屏都无必要承担。且这与仓库既有的 `64A-R1`（ViewModel 只传类型化 `AssetRef`，不传任意路径或像素）**完全一致**——本形态直接继承该决策，不新增例外。

## 3. 双模式：同一感知、两个表达后端

| | **自由模式** | **预设模式** |
|---|---|---|
| 进入条件 | 与主机心跳正常 | **心跳超时 3–5 s**（阈值待实测） |
| 表达来源 | 主机下发（OCLive 实时生成） | **本地规则表**：事件 → 预置表情 + 预置短句 |
| 感知判断 | 完全一致（ESP32 本地采样 + 滤波 + 去抖） | 完全一致 |
| 记忆/成长 | 主机侧持久化 | 无（只播预设，不写记忆） |
| 语音 | 主机侧 TTS（枪上喇叭或主机音箱） | 预置音效 / 短提示音（若装了功放） |
| 切回自由模式 | — | 链路恢复并**稳定 2–3 s** 后才切回，避免反复横跳 |
| UI 提示 | 角落小图标 | 角落显示「离线」标记，让用户知道当前是本地模式 |

**铁律（沿用 `44A-R1`）**：模式切换只改变**表达能力**（信息密度、主动性、语音有无），**绝不改变**握持/举枪判断、感知事实、安全语义与降级行为。也就是说：断连时角色会变"笨"，但状态机与安全行为不退化。

## 4. 上下行契约边界

| 方向 | 内容 | 约束 |
|---|---|---|
| **上（ESP32 → 主机）** | 节点身份 + 低频 `SensorObservation`：握持接触、移动/静止、滤波后方向估计、只读辅助触点、诊断冲击 | 沿用 `28A/29A/30A`：**即时边沿 + 约 1 Hz 快照**；节点内部高频采样、链路只传结论；**断连不补发过期动作**；`boot_id` 每次冷启动变化、`sequence` 单调递增 |
| **下（主机 → ESP32）** | 类型化 `AssetRef`（表情/动画 ID）+ 短文本 + 状态位 + 当前模式 | **不传任意路径、URL 或像素帧**；带 revision，ESP32 只保留最新快照；过期指令直接丢弃 |
| **禁止** | 主机下发原始传感阈值/回写物理事实；ESP32 向 OCLive 发送角色情绪或自由文本 | 感知只产事实、角色只管表达（四职责门禁） |

## 5. 预设触发范围与契约现状（重要）

| 预设触发 | v0.2 契约现状 | 结论 |
|---|---|---|
| **扣动扳机** | ✅ 闭集内：只读 `AuxControlContact(control_id=primary_trigger)` → `control.primary.engaged/released` | **现在就能做**，且只读、不接机构 |
| **举枪 / 放下** | ✅ 闭集内：IMU 方向估计 + 用户校准 → `pose.raised/lowered/unknown` | **现在就能做**；需先做用户校准（两层：安装 transform + 用户姿态样本） |
| **换弹** | ⚠️ **不在 v0.2 闭集**：仓库把余弹/弹匣定为 **G5 之后的 P1+ 只读扩展**（`MAGAZINE_AMMO_ESTIMATION.md`） | **需新增 ADR + 契约版本/能力协商**，不得塞进 P0；建议最小实现是**只读「弹匣在位/拔出」**（弹匣井外侧霍尔/干簧 + 弹匣小磁铁，或纯机械微动），**不做精确弹药计数** |

**另需注意**：ESP32-S3 **没有板载 IMU**（不同于 XIAO nRF52840 Sense），举枪检测必须外挂 MPU6050 / QMI8658。ESP32 用 Wi-Fi 时 **ADC2 不可用**，FSR 必须接 **ADC1（GPIO32–39）**；ESP32 的 ADC 噪声与非线性偏大，需过采样 + 曲线校准，必要时外挂 ADS1115（先实测再决定）。

## 6. 体验由主机性能决定（能力阶梯）

枪侧硬件不变，体验随主机升级——这正是本形态的核心卖点：

| 层级 | 主机 | 可提供的体验 |
|---|---|---|
| **T0** | 无主机 / 断连 | 预设模式：预置表情 + 固定短句 + 状态提示。**永不失效的地板** |
| **T1** | 普通笔记本（无独显） | 本地 3B 级模型（或「选台词」式轻量调用）+ 系统 TTS；记忆/关系持久化 |
| **T2** | 中端独显 PC | 7B 级模型 + 实时 TTS/ASR + 更细的表现（表情过渡、动作反馈） |
| **T3** | 强主机 + P1 扩展 | 以上 + 相机娱乐观察 + 更长记忆/RAG；**仍不做瞄准/火控类功能** |

契约与枪侧固件在 T0–T3 之间**完全一致**：换主机不需要改枪。降级链为 `T3 → T2 → T1 → T0`，任一环节失败都退回下一层，不阻塞感知与安全。

## 9. 待决策与待办

1. **语音时机**：建议**先在自由模式用主机音箱出声**，枪上只留屏幕；待屏幕链路稳定后再评估枪上喇叭（成本 +30–80 元、重量 +20–30 g、功耗显著上升）。
2. **换弹检测方式**：霍尔/干簧（非接触、需防磁干扰）还是微动（接触式、占空间）？决定机械改装量与是否开新 ADR。
3. **屏尺寸与分辨率**：2.0"/2.4" 240×320 起步；分辨率越高，素材容量与刷新带宽压力越大。
4. **素材容量预算**：16 MB Flash 内需容纳字库 + 表情位图 + 音效；需先定表情数量与字库范围。
5. **是否需要 ESP32 侧 IMU 校准向导**（沿用 `IMU_CALIBRATION` 的用户双点 + 动作流程）。
6. **若本形态被接受**：ADR-063 需由 CANDIDATE 升为 ACCEPTED，并同步 `PROJECT_BASELINE.md`、`HARDWARE_IMPLEMENTATION_PLAN.md`、`test-worksheets/采购核对清单.md` 与 `ROADMAP.md` 的对应条目。
