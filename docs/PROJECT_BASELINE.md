## 3. P0交付闭集

**P0-A（当前主线，PC 宿主 + 板上感知）**的交付能力：

1. 板侧驱动采样、去抖和滤波，板上内核处理物理观察。首轮验证运动和重力姿态，其他能力随附件逐项加入。节点按能力集绑定（ADR-065）。
2. ESP32-S3 融合状态并生成变化事件，PC 通过局域网接收设备结果。各状态按实际具备的传感证据判定（ADR-069）。
3. 板侧先给出即时反馈。联机后 PC 的 Output Arbiter 可下发后续的 OCLive 角色表达。
4. 模型失败、链路断连或 renderer 失败时，最低状态界面仍工作；枪侧在断连 3–5 s 内降级到**预设模式**，恢复并稳定 2–3 s 后切回自由模式。
5. 枪侧固件与宿主能自启动；**枪侧能源链可测、可充、可安全降级**。
6. **娱乐后端 G0**（扣扳机 → 主机画面反馈）可玩，且不阻塞以上闭环。
7. 桌面套件通过后，再在悍迪 191 上验证导轨支架、安装净空和场地使用。

**P0-B（独立主机舱，保留后置）**保留原有 6 条闭集与 G4 门，**不因 P0-A 取消**，只是不阻塞近期进度。

PNG/HUD 属于 P0。语音、相机、Live2D、余弹和更多节点不是 P0 完成条件。

## 4. 硬件开发共同基线

### 4.1 首次接线前

- 为每件器件记录实物照片、丝印、卖家链接、批次、接口、标称电压和连接器方向。
- 断电状态检查短路、异物、焊桥、破损、松动和极性；未知针脚不接。
- 先画能源链和信号链，再接线；每条线同时写明起点、终点、电压域、方向和最大预期电流。
- 第一轮主机/屏幕使用可限流台架电源或已知合规成品电源，不直接设计最终电池包。

### 4.2 Bring-up固定顺序

```text
到货身份与外观
→ 断电电阻/连续性/极性
→ 主板单独上电与串口/系统
→ 屏幕单独供电
→ 视频链
→ USB触摸
→ Host与最低UI
→ 单个BLE节点USB供电
→ 第二节点
→ 双节点共存
→ 节点受保护电池
→ 主机移动电源
→ 外壳与机械假体
→ 上枪静态
→ 场地
```

每一步只增加一个新变量；失败时回到最近一次已通过状态。不得在同一次首次上电同时接主板、屏幕、电池、传感器和未知转接件。

### 4.3 测量与停止规则

- 通电前测极性和断电电阻；通电时先看限流、电压跌落、异常热和气味，再看软件日志。
- 不带条件、仪器、测点、批次和revision的数字不能标记为`MEASURED`。
- 电芯鼓胀/破损、异常升温、极性不明、连接器发热、重复brownout、屏幕反供电或机械件改变原机构动作时立即断电并隔离。
- P0 附件与载体火控、电机、供弹和执行线路隔离。

## 5. 软件与接口基线

- Rust 类型是当前 v0.3 感知契约真源，Schema 由代码生成。 [ADR-067](DECISIONS.md#adr-067节点模型泛化落地单板形态强制契约-v03角速率改走独立指向流)
- 感知内核可独立于 OCLive、BlueZ、GPIO、SQLite 和屏幕运行。P0-A 的板侧固件组装驱动和感知，PC Host 组装 OCLive 侧的角色链路。 [ADR-069](DECISIONS.md#adr-069p0-a-由-esp32-s3-运行感知内核)
- 节点驱动滤波后给感知内核提供观测，Host 向 OCLive 提供有界的类型化事实。
- 系统提示高于角色提示；迟到RoleCue不得覆盖更新的物理revision。
- 本地3B及以下模型只是可失败表达provider，不阻塞感知、UI、持久化或关机。

## 6. G4完成定义

满足以下条件才称“实体硬件闭环完成”，不能只以“屏幕亮了”或“BLE连上了”代替：
