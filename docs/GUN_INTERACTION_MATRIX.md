# 枪械联动候选矩阵（P0-A 虚拟靶场配套）

**状态**：`CANDIDATE`（2026-11-13；所有者要求「先把枪械互动列全，再做减法，先做好做的」）
**唯一职责**：枚举**可被观测的枪械动作**，按「契约成本 × 对靶场的价值 × 台架可证伪性」做减法，给出 MVP 顺序。
**不负责**：界面与表情映射（`FRONTEND_DESIGN_BRIEF.md` §9）· 传感器与接线（`SENSOR_OPTIONS.md` §P0-A）· 帧协议（`PROTOCOL_V1_DRAFT.md`）· 契约字段（`crates/ailive-gun-spirit-contracts` 为真源）

## 1. 判据（先定判据，再做减法）

| 判据 | 要求 |
|---|---|
| **红线** | 只读、外部、可逆：**不进机匣/波箱、不接火控/电机/供弹、不改变任何机构的行程与手感** |
| **契约成本** | C0 = v0.3 闭集内零改动 · C1 = 扩既有枚举成员 · C2 = 类型已有但内核未融合 · C3 = 需新消息/新版本 · C4 = 禁止 |

## 4. MVP 顺序（先做好做的）

| 序 | 项目 | 为什么排这里 | 额外硬件 |
|---|---|---|---|
| **P1** | 扣扳机（11） | 已在做，靶场最基础输入 | 霍尔 + 磁铁 |
| **P2** | **肩托抵肩（3）** | **最便宜的高价值件**：把"举枪"从"IMU 猜姿态"升级为"物理上真的抵肩"；与 FSR **同一套分压电路**，只是多一片 | 一片压感 |
| **P3** | 拉枪栓/枪机（7+8） | **先用 IMU 冲击零成本验证**；判不出来再贴磁铁+霍尔 | 0（先） |
| **P4** | 手电/保险（18/19） | 简单数字输入，但**先确认载体上有没有** | 无（若有现成触点） |
| **P5** | 换弹（14+15+22） | 玩法核心，但要新契约版本 | 霍尔 + 弹匣磁铁 |
| **P6** | 弹药粗范围（16） | 最后，且**只粗** | 磁性随动件 |

**核心判断**：**肩托是"最便宜的高价值件"**。它同时改善两件事——① 角色反馈（抵肩=进入专注/瞄准，比姿态猜测稳）；② 玩法判定（狙击/精确射击需要"真的抵肩了"这个事实）。而它只是 FSR 电路的第三片。

## 6. 与虚拟靶场的接口（边界提醒）

- **换弹/拉栓 → 玩法计时与「装填中」状态**；**扳机 → 射击输入**；**肩托/举枪 → 瞄准姿态**；**弹药粗范围 → HUD**（仅粗粒度）。
- **命中与得分是游戏事实**，必须有独立 provenance，**不得**作为 `DeviceEvent` 注入感知内核（ADR-066 / `PROJECT_BOUNDARIES.md` §6）。
- 上述任何动作都**不表示击发、命中或伤害**；契约里 `control.primary.engaged` 只证明**触点状态**。
