# 弹匣余量融合扩展设计

状态：CONCEPT ACCEPTED / P1+ DEFERRED / 尚无实机证据  
更新时间：2026-08-28  
适用项目：`A.I.Live-ai枪娘器灵`，不属于 OCLive 通用内核

## 1. 目标与边界

本扩展为 wargame 发射器提供粗粒度余弹感知。它使用“发射循环短计数”保持连续变化，使用“磁性随动件 + 外部霍尔阵列”提供绝对范围锚点，两者互相校正。面向用户的第一目标是稳定显示`full / three_quarters / half / quarter / low / unknown`，不是承诺精确到颗。

本设计不进入 P0，不阻塞当前传感器—本地 OCLive—屏幕闭环。只有 ROADMAP G5 通过后才允许建立独立原型切片。所有电子部分只读；不得控制、串联、切断或改变原发射器的扳机、火控、MOSFET、电机、供弹和机械行程。任意传感器、节点、程序或电池故障只能让余量变成`unknown`，不能让弹匣停止或改变供弹。

“发射循环完成”只表示波箱完成一次可观察循环，不等于水弹已经成功离开供弹管或发射器。除非未来增加并验证逐弹通过传感器，否则文档、UI和角色表达均不得把循环数称为实际发射颗数。

## 2. 为什么使用双源融合

| 信息源 | 能确认什么 | 不能确认什么 | 本设计职责 |
|---|---|---|---|
| 发射循环 | 机械循环的连续次数和时序 | 空击、卡弹和供弹失败时是否真的消耗水弹 | 高频连续估算 |
| 磁性随动件 + 霍尔阵列 | 稳定姿态下弹仓或托弹板的大致绝对位置 | 运动中精确颗数；散装水弹堆表面并不平整 | 初始化、范围锚定和纠偏 |
| 弹匣拔插/会话边界 | 何时结束旧弹匣会话 | 新弹匣实际装填量 | 允许复位或重新装填 |
| 未来逐弹通过传感器 | 有水弹实际经过检测点 | 检测点之后是否成功完成全过程 | 可选增强，不是当前前提 |

单独使用循环计数会持续累计误差；单独使用浮板会受到倾斜、震动、装填方式和机械卡滞影响。双源融合把误差限制在两个可信锚点之间，并能显式发现两种传感结果冲突。

## 3. 发射循环观察链路

### 3.1 信号语义

必须分清以下事件：

```text
trigger contact
    只是扳机/辅助触点状态

motor energized
    只是电机得到驱动

mechanism cycle completed
    波箱或与其一比一联动的运动件完成一圈

projectile passed
    水弹确实经过独立检测点
```

连发时一次持续的`trigger contact`可能对应多个`mechanism cycle completed`。P1+余量估算的主计数源必须是第三项或更强证据，不能用一次扳机按下代替整段连发的循环数。

### 3.2 检测优先级

RADIAN 2.0 火控是否提供可复用循环传感器或可读输出尚无公开、可验证资料，实机拆检前标记为`UNKNOWN`。检测路线按以下顺序裁决：

1. 火控存在循环传感器且提供明确只读输出：优先读取。
2. 火控内部存在循环传感器但无输出：评估高阻抗缓冲或数字隔离的只读旁路；不得改变原传感器负载和时序。
3. 电动回膛件与波箱经实测严格一比一：在不改变机构行程的位置增加独立霍尔或光电观察。
4. 增加独立的齿轮/运动件循环传感器，并保持物理失败开放。
5. 电机电流波形、机匣震动或声音分类只作为低可信度回退，不得未经实测承担精确主计数。

未知火控信号不得直接连接 XIAO GPIO。先在断电状态确认线路，再使用万用表、逻辑分析仪或示波器测量电压域、极性、共地关系、边沿宽度和启动瞬态；需要时通过光耦、数字隔离器或经计算的高阻抗缓冲进入节点。

### 3.3 数据流

```text
火控/独立循环观察点
  → 电气隔离或高阻缓冲
  → 本地MCU GPIO中断与去抖
  → 低频批量/边沿Observation
  → Host短计数与融合
```

循环观察只产生事实，不允许反向驱动火控或电机。若内部短线不可维护、会妨碍原机构或电子节点故障会改变发射器行为，则该安装方式直接否决。

## 4. 磁性绝对位置观察

### 4.1 散装电动水弹弹匣

候选结构是接近弹仓截面的低重心随动浮板。浮板使用半圆/D形低位结构降低晃动倾向，左右两侧使用有余量的纵向导向耳或导轨保持磁铁方向。这里的“卡位”只表示防脱导向，不得设计成会在若干高度咔哒停住的离散档位。

机械要求：

- 导向槽决定姿态，低重心只辅助抑制翻转和拍击；不能只依靠重力自稳。
- 导向耳采用圆角、小接触面和可实测间隙。首轮打印可从单侧约`0.5–0.8 mm ESTIMATED`试起，最终必须按内腔、材料、吸水/碎弹和打印误差实测。
- 磁铁固定在靠近霍尔阵列的一侧，防旋转、密封，不得突出到供弹路径。
- 浮板、磁铁和限位失效时仍不能进入电机、输送轮或供弹管；供弹口上方必须有独立机械隔离/限位。
- 允许设置小于水弹直径的排水/通气孔和圆滑泄污结构，但不能形成夹弹缝隙。
- 浮板质量、摩擦和接触压力不能显著压伤水弹或改变供弹成功率。

装填是当前最大机械开放项：如果原弹匣从弹仓上方倒入水弹，整片浮板会挡住新弹，甚至被埋到弹堆中。实机必须在以下路线中选择一种：装填时将浮板提起并停靠顶部、让现有/新增侧向加弹口位于浮板下方，或否决整片浮板并改用其它绝对测量方式。首版不采用复杂自开合栅格。

### 4.2 弹簧供弹弹匣

弹簧供弹不增加独立浮板。优先在原托弹板后方或非受力侧设计小型隐藏磁铁座，让原托弹板位置直接成为绝对位置：

```text
弹丸队列 → 原托弹板 → 隐藏磁铁座 → 原弹簧
                         ↓
                    外部霍尔阵列
```

磁铁座不得改变托弹板外形、抗倾斜能力、弹簧压缩长度、供弹压力和拆装。若无法做到失败开放，则放弃该适配件。

### 4.3 外部弹匣套与霍尔阵列

弹匣内部只保留无源、密封的小磁铁或磁铁座；霍尔传感器、MCU、可能的 BLE 和电池放在机械锁定的外部弹匣套中。弹匣套依靠非磁性机械基准定位，内部小磁铁只是测量目标，不承担安装固定。

首轮使用`4–5个模拟霍尔传感器 ESTIMATED`沿有效行程分布，记录完整传感器向量而不是把单颗霍尔值直接当距离。最终数量、间距、磁铁牌号/尺寸、极性、外壳间隙和抗电机磁场设计由实测冻结。单颗霍尔远距离测距和仅靠数字霍尔档位均不是默认路线。

弹匣套的供电和无线拓扑尚未冻结。台架优先有线连接开发板；产品候选是独立低功耗 BLE 弹匣节点，或在短线可维护且不妨碍换匣时接入附近节点。不得在没有续航、换匣、跌落和体积数据前直接复制 XIAO 节点电池方案。

## 5. 短计数与范围融合

### 5.1 两类计数器

Host至少区分：

- `lifetime_cycle_count`：用于维护、耐久和诊断的长期累计，不直接表示当前余弹。
- `cycles_since_anchor`：从最近一次可信霍尔锚点或明确装填确认开始的短计数；每次建立新锚点后归零。

短计数避免从满匣一直积累到空匣的不可控漂移。正常供弹假设下，每个可信循环让点估算减一；由于循环不等于实际过弹，随着短计数增加，结果范围必须扩张或证据强度下降。

### 5.2 会话和锚点

建议状态：

```text
mag_absent
  → settling
  → tracking
  → uncertain | sensor_fault
  → mag_absent
```

建立霍尔锚点至少需要：弹匣已识别、姿态满足该弹匣校准条件、短时间低加速度/低震动、霍尔向量连续稳定。具体角度、稳定窗口和方差阈值均为 HostProfile/实测值，不进入跨组件常量。

同一次装匣会话内，真实余量默认单调不增加。霍尔读数偶然向上跳时先拒绝；只有检测到弹匣拔出、进入明确装填模式或用户确认重新装填后才允许余量上升。弹匣身份不得用 BLE RSSI 猜测；多弹匣必须有稳定`magazine_id`或明确的活动弹匣选择。首个原型只验证一个智能弹匣。

### 5.3 融合和冲突

1. 新会话先由霍尔给出绝对范围；若用户明确确认满装，可使用该确认建立更窄锚点。
2. 运动和连续射击期间，使用`cycles_since_anchor`更新点估算和范围，不要求浮板实时追踪。
3. 枪身重新稳定后读取霍尔向量。若与当前估算相容，取交集/收窄范围并重置短计数。
4. 若连续可信霍尔观察与循环估算不相容，不允许悄悄跳数；进入`source_conflict`，降低证据强度并保留两侧诊断。
5. 不从一次异常自动重写容量或传感器标定。每档有效循环数使用多次会话的稳健统计更新，且必须可回滚。

内部可以保存连续点估算和上下界；面向用户默认只显示粗档位。范围跨越多个档位或任一关键源故障时显示`unknown`或“余量需要确认”，不能为了画面稳定伪造确定值。

## 6. 未来接口契约

P0 v0.2 的`SensorObservation / PerceptionState / DeviceEvent`闭集保持不变。本设计实施时必须先新增独立版本/能力协商和失败测试，不能把字段塞进 v0.2 或用自由文本绕过。

未来语义至少需要区分：

```text
MechanismCycleObservation
  = 完成一次可观察机械循环

MagazineLevelObservation
  = 在指定姿态/稳定条件下观察到霍尔范围

MagazineTelemetryState
  = 融合后的档位、点估算、上下界、证据强度和故障状态
```

推荐状态字段（名称在实现前通过ADR/Schema正式冻结）：

- `magazine_id / magazine_session_id`
- `display_band`
- `estimated_count`（可空，禁止包装为绝对真实）
- `lower_bound / upper_bound`
- `confidence_milli`（证据强度，不是统计概率）
- `cycle_source_status / hall_source_status`
- `reason: normal | settling | uncalibrated | source_conflict | node_offline | sensor_fault`

每个循环不得自动创建角色回合。Host/Output Arbiter可以即时更新 HUD；只有低余量、档位变化或故障等受限语义才可能经未来伴随包和 Input Scheduler 触发低频角色反应。OCLive只接收规范化余量上下文，不读取霍尔ADC、火控电平、磁铁位置或错误堆栈。

## 7. 故障降级

| 故障 | 降级行为 | 禁止行为 |
|---|---|---|
| 循环源丢失 | 使用最近可信霍尔粗档位，标记连续估算不可用 | 假装循环仍在计数 |
| 霍尔源丢失/浮板卡住 | 继续短期循环估算并逐步降低证据强度 | 永久沿用旧绝对档位 |
| 两源冲突 | 输出`source_conflict/unknown`，保存诊断 | 无记录地强制相信任一侧 |
| 弹匣套断电/BLE断连 | 余量变Unknown，基础发射器继续原样工作 | 因遥测失败禁止供弹或发射 |
| 磁铁缺失/饱和/受电机干扰 | 隔离霍尔源并提示校准/维修 | 用异常向量重新训练正常标定 |
| 装填未确认 | 给出宽范围或Unknown | 默认当作满匣 |

## 8. 实机验证顺序

1. 拆检备用弹匣，记录内腔截面、有效行程、供弹轮/供弹管、加弹口、排水和可安装导轨空间。
2. 确认 RADIAN 2.0 火控/回膛是否存在可读且一比一的循环事实；分别测试单发、连发、预供、空击、堵转和低电。
3. 先用无磁浮板假体完成装填、倾斜、晃动、跌落、碎弹/水分和供弹失败开放测试，再安装磁铁。
4. 在`0 / 约1/4 / 约1/2 / 约3/4 / 满装`五个实际装填点采集霍尔向量；档位按真实可用颗数标定，不假设行程与数量线性。
5. 弹匣套重复拆装至少20次，验证机械基准重复性；每个装填点在竖直、水平、倾斜、摇晃和电机运行状态重复采样。
6. 对浮板/托弹板做至少500次往返早期验证，产品候选做1,000次；检查卡滞、磨损、磁铁密封、摩擦和供弹成功率。
7. 记录循环漏计/重复计数、霍尔错档、两源冲突、重建锚点所需时间和每档实际循环分布。
8. 只有机械失败开放、电气隔离和供弹无回归先通过，才进行场地测试。

原始记录使用`test-worksheets/07-余弹融合与弹匣结构测试表.md`。所有尺寸、间隙、阈值、传感器数量、容量映射、准确率和续航在获得证据前均为`ESTIMATED`或`UNKNOWN`。

## 9. 当前未冻结项

- RADIAN 2.0 火控是否有循环传感器、数据输出或可安全旁路观察点。
- 电动回膛是否与波箱循环严格一比一。
- 原装弹匣内部几何和加弹口是否允许整片导向浮板。
- 浮板材料、质量、半圆/D形比例、导向间隙、磁铁尺寸与密封方式。
- 霍尔数量、间距、采样率、温漂和电机/钢件磁干扰。
- 弹匣套是独立 BLE 节点还是接入附近节点，以及电池、充电和换匣体积。
- 多弹匣身份、装填确认和活动弹匣切换方式。
- 未来契约版本、事件闭集、HUD呈现和角色低频反应策略。

这些开放项必须由实物和回放数据填空，不得因本设计已记录就视为完成。
