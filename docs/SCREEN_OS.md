# 屏幕操作系统设计（板上 UI）

**状态**：`CANDIDATE`（2026-11-14；部分已实现）
**范围**：480×320 触屏上的**运行结构与页面体系**——分层、页面清单、导航、状态机、数据来源、触摸约定、性能预算、降级行为。
**不负责**：表情与感知映射（`FRONTEND_DESIGN_BRIEF.md` §9）· 固件任务模型（`P0A_FIRMWARE_PLATFORM.md`）· 场景玩法（`SCENARIO_FORMAT.md`）

> "屏幕操作系统"不是独立 OS：它是 **LVGL 之上的一套页面与状态管理**，随固件一起编译。

---

## 1. 设计取向

| 取向 | 说明 |
|---|---|
| **角色永远是主角** | 默认页面只有角色；信息以叠加层出现，不抢舞台 |
| **一个屏幕一个焦点** | 同一时刻只有一个"焦点层"接收触摸 |
| **状态可见、可解释** | 在线/离线/配网/错误都要**明确显示**，不假装正常 |
| **不打断即时反馈** | 任何设置页/弹窗都不得阻塞表情与触摸响应 |

---

## 2. 分层

| 层 | 内容 | 层级 |
|---|---|---|
| `CharacterStage` | 260×260 立绘 + 情绪名 + `n/7` | 底层（默认） |
| `OverlayHUD` | 模式（在线/离线/靶场）· 连接 · 电量/电源 · 帧计数 | 中（常驻细条 ≤28 px） |
| `SystemOverlay` | 设置页、配对、诊断、错误提示、聊天提示 | **顶层（独占触摸）** |

**约定**：`SystemOverlay` 出现时，角色停止接收触摸但**继续渲染**（不做黑屏），退出后恢复。

---

## 3. 页面清单

| # | 页面 | 内容 | 进入方式 | 状态 |
|---|---|---|---|---|
| **P0** | **角色主屏** | 立绘、情绪名、`n/7`、Prev/Next、右上角设置按钮 | 默认 | ✅ 已实现 |
| **P1** | **连接** | Wi-Fi 状态、SSID、IP、电脑连接状态（**只读**） | 设置 → 连接 | ✅ 已实现（只读） |
| **P2** | **预设** | 交互预设列表（举枪→表情、握持→表情…），逐项启用/禁用 | 设置 → 预设 | ⏳ |
| **P3** | **音量** | 语音/音效音量（**控制 PC 侧播放**；板载音频不在 P0） | 设置 → 音量 | ⏳ |
| **P4** | **诊断** | 固件版本、内核 ABI/修订、IMU 状态、内存、协议帧计数 | 设置 → 诊断 | ✅ 已实现 |
| **P5** | **配对/绑定** | 无线传感器模块的添加/重绑/解绑/电量 | 设置 → 模块 | ⏳（等模块） |

**导航**：角色主屏右上角**设置按钮**进入；设置内用"返回"退出。**刻意不做长按**——电容屏上长按容易误判，一个明确的按钮更可靠。**不做多级滑动导航**（小屏易误触）。

## 4. 运行状态机

```
        ┌──────────┐  有凭据且连上路由     ┌───────────┐
  BOOT ─►│  IDLE    │ ──────────────────► │  ONLINE   │
        │ (离线)    │ ◄────────────────── │ (PC 已连) │
        └──────────┘   断连 > 5 s         └───────────┘
             │  ▲                                │
     长按进入 │  │ 退出                          │ 收到 EXPR/EVENT
             ▼  │                                ▼
        ┌──────────────┐                  ┌───────────┐
        │  SETTINGS    │                  │ 角色表达  │
        └──────────────┘                  └───────────┘
             │
             ├─ 配网失败/协议错误 ─► ERROR（可返回）
             └─ 资产加载失败     ─► DEGRADED（继续可用）
```

| 状态 | 角色行为 | HUD 显示 |
|---|---|---|
| `ONLINE` | 跟随 PC 的 `EXPR`/`EVENT` | `● 在线` |
| `IDLE`（离线） | **本地预设轮转**：静止→`neutral`，触摸→轻微反应 | `○ 离线` |
| `SETTINGS` | 继续渲染，不接收触摸 | `⚙ 设置` |
| `ERROR` | 停在 `confused` + 遮罩说明 | `！错误` |
| `DEGRADED` | 正常角色，但资产/内核缺失时用占位 | `△ 降级` |

## 5. 数据来源（单一真相）

| 数据 | 来源 | 优先级 |
|---|---|---|
| 当前表情 | **PC 的 `EXPR`** 或 **本地预设**（离线时） | 手动覆盖 5 s → 感知自动 → 默认 |
| 感知状态 | 板载内核 → 帧协议 | 断连时显示 `unknown` |
| 连接状态 | `wifi_link` | 实时 |
| 预设列表 | 发行版（`reactions.json`/`presets.json`） | 安装后生效 |
| 音量 | 本地 NVS → 通过帧协议下发给 PC | 立即生效 |

**原则**：屏上不缓存"第二份状态"。所有显示值都从**当前唯一来源**读取，避免出现"屏上显示在线但实际已断"这类不一致。

## 6. 双屏一致（与电脑同内容）

电脑侧同时渲染两块内容：

| 电脑界面区域 | 内容 |
|---|---|
| 主视口 | 场景（靶场/训练场） |
| **镜像面板** | **与枪上屏完全相同的 `CharacterStage` 渲染**（同一状态源、同一布局比例） |

这样"枪上屏幕和电脑里的枪械屏幕显示相同内容"是**同一份 ViewModel 的两个渲染器**，而不是两边各自实现。

**双屏互动（NDS 式）MVP 候选**：

| 玩法 | 上屏（电脑） | 下屏（枪上） |
|---|---|---|
| 干扰/加油 | 目标加速/减速 | 触摸角色 → 发送一次"干扰"信号 |
| 情绪同步 | 命中/失误改变场景氛围 | 角色表情同步变化 |
| 提示 | 场景给出提示图标 | 角色用手指/气泡指方向 |

**限制**：下屏所有输入只能影响**游戏表现**，不得影响命中判定本身（避免变成辅助瞄准）。

## 7. 触摸约定（最小手势集）

| 手势 | 位置 | 行为 |
|---|---|---|
| 单点 | 左/右底部区 | 上一个/下一个表情 |
| 单点 | 角色区域 | 角色短反应（本地预设） |
| 单点 | 右上角设置按钮 | 进入设置（已实现） |
| 长按 2 s | 设置内"连接"页 | 重新配网（清凭据前需二次确认） |

**不做**：双指、滑动、双击（小屏误触率高）。

## 9. 降级行为

| 故障 | 屏上表现 |
|---|---|
| 资产加载失败 | 占位色块 + HUD `△ 降级`；设置页可用 |
| 内核未初始化 | 表情仍可由 PC/本地驱动；感知相关 HUD 显示 `unknown` |
| PC 断连 | 切 `IDLE`，本地预设接手；HUD `○ 离线` |
| Wi-Fi 未配置 | 设置 → 连接页给出"未配置"与操作提示 |
| 帧协议错误 | HUD 角标计数（不弹窗打断角色） |

## 11. 字体与文案纪律（2026-11-14 定）

**问题**：LVGL 自带字体只有拉丁字母；内置 `lv_font_simsun_16_cjk` 覆盖约 1000 个常用字，但**缺当前 UI 用到的 33 个字**（实测），中文会显示为方框。

**做法**：

| 项 | 决定 |
|---|---|
| 字体 | 用 **SimHei 生成子集** `lv_font_ui_16`（16 px、4 bpp、ASCII 0x20–0x7F + 代码中实际出现的 79 个汉字） |
| 体积 | 字库 `.c` 约 96 KB 文本 / 目标文件约 13 KB；**静态 flash，不占 RAM**（实测打开设置层只多约 400 B） |
| 生成 | `./scripts/build-cjk-font.ps1`；需要 `node` + `lv_font_conv` |
| 校验 | `./scripts/build-cjk-font.ps1 -Check`：若 UI 里出现字库没有的字则 **FAIL** |
| 注释 | 收集字符前**先去掉注释**——注释里的中文不该进字库（曾因此把字库从 13 KB 撑到 50 KB） |

**纪律**：**任何新增中文文案都必须重跑生成脚本**，否则上线即方框。文案尽量短（16 px 下每行约 28 个汉字，480 px 宽）。


## 12. 上板验证记录（2026-11-14，MEASURED）

触摸链路一度被判断为"点不动"，用串口探针 `TOUCHDBG on` 读出 LVGL 输入设备的原始坐标后确认：**触摸本身完全正常**。

| 点击位置 | 实测坐标 | 事件 |
|---|---|---|
| 屏幕中央 | (254,164) | —（内容区，无按钮） |
| 右上角「设置」 | (436,41) | `SETTINGS shown` |
| 「诊断」页签 | (286,76) | `SETTINGS tab=1` |
| 「连接」页签 | (51,69) | `SETTINGS tab=0` |
| 「返回」 | (417,81) | `SETTINGS close` → `SETTINGS hidden` |

**真实原因（两个实现缺陷，均已修）**：

1. 首版把"设置入口"按钮的插入**静默失败**，设置层根本没有入口——用户点「返回」后再也进不来；
2. 页签/返回用 `lv_obj_create` 创建，**该函数默认不加 `LV_OBJ_FLAG_CLICKABLE`**，点击没有事件。

**最终实现**：设置层为**独立 LVGL 屏幕**（`lv_obj_create(NULL)` + `lv_scr_load` 切换），按钮统一用 `lv_btn_create`（与主屏已验证可用的 Prev/Next 同类）；中文用 SimHei 子集字库。

**诊断命令**：`TOUCHDBG on|off`（每 200 ms 打印输入设备坐标）、`SETTINGS on|off`（串口开关设置层，无需触摸）。
